## 2. 研究问题、假设和预期强度

RQ1：保持模型与需求不变，AST 表示和真正的受限解码分别减少多少格式/规则匹配失败？

RQ2：语法有效的契约中，是否仍存在错对象、错阈值、遗漏约束与错误组合？额外静态检查能拦住哪些？

RQ3：同一份契约面对相同正确/错误产物时，能否做出正确判定？在包含失败与修补费用后，是否降低每份可靠契约的成本？

预设三项假设：

- H-F：在后端真实支持且生成完整结束的 Schema 子集上，受限解码提升结构有效率。证据较强，但全请求有效率仍受超时、拒答、截断与特性不支持限制。
- H-S：引用/类型/操作检查能检出其明确定义范围内的错误。它不能证明选中的合法检查和阈值符合用户意图；降低整体误接纳是待测假设。
- H-E：格式修补减少可能降低规划总成本，但若原基线已几乎无格式错误，或 AST/解码开销更大，收益可能很小或为负。暂不预言固定降本比例。

## 3. 对照设计：三种生成方式 + 一个嵌套校验策略

旧方案一次上五种独立生成策略，不适合作为本机起步。改为如下对照，更容易归因并节约调用：

| 组 | 生成内容 | 解码 | 后处理 | 能回答的问题 |
|---|---|---|---|---|
| A：冻结基线 | 当前 acceptance 字符串和原任务外壳 | 普通 | 运行副本的冻结校验器与 verifier | 当前真实做法的表现 |
| B：AST 提示 | 带类型的 AST，外壳不变 | 只靠提示词要求，事后校验 | Schema+共同解释器 | A→B：表示及其必要说明的总效应 |
| C：AST 受限 | 与 B 完全相同的 AST | 真正受限解码 | 与 B 相同 | B→C：解码限制的贡献 |
| D：C+静态检查 | **复用 C 的同一份原始输出** | 与 C 相同 | 再查引用存在、参数/操作兼容、检查可启动等 | C→D：额外检查策略的增量效果 |

D 不是第 4 次独立模型生成，不能增加独立样本数或声称改善了首稿生成本身。它能改变接纳/拒绝、错误归因与执行路径，不能改变首稿原文是否忠实。C/D 在同样输出上的配对，是控制生成随机性的机制消融。

如果静态检查已编码在 C 的 Schema 中，不能再次当成 D 的新能力。逐项登记 enforced_by_schema、enforced_by_static_check、checked_by_execution；D 的新增项必须确实是 C 未检查的上下文条件。

### 3.1 模型和调用控制

优先选择一个已验证可用、且**同一模型快照与接口**支持普通和真实受限输出的后端，预实验确定。不是默认假定现有 Codex CLI 或 deepseek-flash 支持该开关。只有提示 JSON、自动抽取代码块或解析失败后重试，都不算受限解码。

如果现有后端没有该能力：先开展 A/B 和固定输出上的 D 静态检查试验；B/C 主对比保持待开展。不能用 H 普通生成对 L 受限生成，或拿不同壳的结果声称纯解码效应。若要换统一实验后端，整个 A/B/C 都在该后端运行，再另报与实际生产模型的差异。

每组相同原始需求、目录/对象目录、公开检查文档、上下文上限、最大输出及超时。相同 token 上限在预实验中确保足以容纳完整最大 AST；正式输出仍被截断时记失败，不扩容重跑。提示中的表示说明与示例是必要干预，保留全文并计 token，A/B 的差别不声称是“只换括号”。

## 4. AST 的范围与冻结接口兼容

只研究当前可明确判定的内容层操作：RUN_CHECK、FILE_EXISTS、TEXT_CONTAINS、SYMBOL_EXISTS、ALL/ANY/NOT。优先使用已登记命令；不让模型任意构造新测试再自己打分。不纳入美观、流畅、综合产品体验等没有独立真值的要求。

示意需求：“标题为空应拒绝，既有创建行为保持不变。”

```json
{
  "op": "ALL",
  "items": [
    {"op": "RUN_CHECK", "check_ref": "reject_empty_title", "expect_exit": 0},
    {"op": "RUN_CHECK", "check_ref": "create_regression", "expect_exit": 0}
  ]
}
```

这个 AST 可以完全合法，却把目标检查换成另一个合法 check_ref，或把 ALL 写成 ANY；所以必须另外评价意图和实现判别。存在一个检查不代表该检查检验了用户真正要求的内容。

A/B/C/D 都获得相同对象/检查目录，包含相关与合理干扰项，文档信息完全相同；不能只给 AST 组 gold ID 或把答案枚举进 Schema。目录是可用工具规格，不是答案表。缺失真实检查的情况由专门边界样本考察，不把主任务装置故障伪装成难题。

研究 AST、Schema、检查器和解释器置于未来的独立研究适配层，不直接改变冻结版 Task.acceptance 的类型或 E014 语义。现阶段仅设计。后续若要通过 Orch 执行，只将研究解释结果经冻结、可审计的转换映射到原生可执行形式；所有组保留原始输出与转换记录。公共操作在 B/C/D 使用同一个解释器，避免某组多获得一种能力。

若比较 A 的模型 judge 与 AST 确定式执行，额外单列“只含现有确定式命令”的 A 子集；否则优势可能来自替换了评分者而非仅 AST 格式。A 的实际 judge 费用与波动照实记录。

## 5. 数据集：先本机核心集，再公开外部验证

### 5.1 核心 T2-local：24 个新需求家族

以当前本机可运行能力为准：12 个代码任务、12 个文档内容任务；各至少 3 个独立项目/主题，每项目/主题不超过 4 题。24 题必须来自 24 个不同基础需求家族，同一需求的换名/改写不算新题；共享项目的回归测试和来源相关性另记。全部为未用于既有 E40—E43 调试的新题。既有失败例只用于开发和构造错误分类，不进入正式有效性估计。

| 类型 | 配额 | 约束内容 |
|---|---:|---|
| 代码对象定位与返回行为 | 4 | 文件/函数、返回值、错误处理 |
| 代码输入边界 | 4 | 空值/边界/类型等，配明确例子 |
| 代码组合与回归 | 4 | 同时满足两个行为，保留旧接口 |
| 文档文本与禁用内容 | 4 | 必备条目、禁止占位符、字面文本 |
| 文档结构与编号 | 4 | 小节、编号连续、条目数量 |
| 文档来源对应与组合 | 4 | 对应给定记录、不得遗漏/重复、多个条件同时满足 |

优先用普通文本/Markdown 和本机 Python 检查；如包含办公格式，使用仓库现有确定性内容工具，另记格式，不把版式质量混入。每条需求 2–4 个原子约束，至少一个能被“合法但无关的检查”混淆的干扰项；干扰项是公开工具目录的一部分，所有组一致。

每题准备：两份实现方式不同但都正确的产物，四份错误产物（关键行为缺失、边界错误、旧行为/保持约束破坏、组合/对象错误），共 **144 份候选产物**。独立参考检查为这些产物给出 gold，模型生成契约时不能看候选及隐藏测试。不能假定公开 gold patch 或原版本天然提供六份候选。

代码和文档分层报告；文档“通过”仅表示约定内容层约束满足，不能外推写作质量。正确性标签由两名独立审查者核对需求与证据后裁决，先不看生成结果，防止只造 AST 擅长检出的缺陷。

### 5.2 独立固定契约集 V2-mini：60 份

从不同于 T2-local、预实验的额外 12 个需求家族构造，每家族 5 份：正确契约、结构错误、静态引用/类型错误、语义偏移、空洞/削弱，各 12 份。每份制作 N/AST 的可比表示；不可比缺陷标记 not_comparable，不把丢 JSON 逗号与删语义条件硬配对。

这部分不让模型生成，检验 A、共同 AST 校验器及 D 的拒绝边界。错误类型由人事先指定，不能根据哪个组失败来挑反例。结构、引用/类型错误有明确 gold；“错选合法检查”等意图错误不能期待普通 Parser 自动检出。

### 5.3 外部 J2-small：JSONSchemaBench 60 个 Schema

从固定 revision 抽样：标量约束、对象字段、数组、组合/引用四类各 15。规范化摘要去重，多特性按组合引用→对象→数组→标量归主类；主层内随机，记录原来源与难度。正式前另留 8 个开发 Schema，按来源/家族隔离。

同模型普通输出与受限输出各生成 1 次：**120 次外部生成**。全部样本有效产出率、已支持子集有效率、后端支持覆盖、编译/生成时间与 token 分开报告。独立标准校验器评分，不能以解码器自己报告成功作 gold。不支持特性留在覆盖分母，失败/截断不删除。

为什么选它：作者公开了真实 Schema 汇集与效率、覆盖、质量的评测框架，直接对应受限解码问题；但这部分没有统一任务意图 gold，只能为结构层提供外部证据。[JSONSchemaBench 论文](https://arxiv.org/abs/2501.10868)、[官方代码](https://github.com/epfl-dlab/jsonschemabench)

### 5.4 标准符合性 Q2-small：官方 Test Suite 200 个实例

固定同一 draft（默认 2020-12，后端适用性预实验确认），从 [JSON Schema Test Suite](https://github.com/json-schema-org/JSON-Schema-Test-Suite) 选正负各 100，四个主特性层各 50、正负各 25。同 Schema 家族最多 10 例，开发/正式按整个家族划分；远程资源冻结本地，optional 特性单列。若数量不足，R0 前修订配额，不假装已抽到。

保留官方 valid 标签；支持范围内误判为实验装置错误，先定位再开展正式比较。Q2 不调用模型，不评价自然语言理解，不给不接受通用 JSON 实例的 A 组强行记零分。它与 V2-mini 的语义错误不是同一种样本。

### 5.5 BFCL：第二阶段外部语义复验，不列入首轮必跑

从冻结 BFCL 的 simple、multiple、parallel、irrelevance 单轮类别各 10 个，共 40 个基础家族；优先离线 Python 规格。再从 8 个不同母题各派生一个缺参数或缺能力变体，各 4，共 48 个输入/40 家族。变体人工复核：删掉的信息不能由剩余上下文推得；剩余工具不能替代缺失能力。

各输入运行 A/B/C 三种表示各 3 次，D 复用 C，共 432 次生成。该外部试验采用独立工具调用契约适配，而非声称当前验收 DSL 自动等同函数调用。原工具文档、可接受答案集合、缺参数/缺能力原因、顺序/并行等价及额外调用全部标注；原生与派生题分开。分数称 BFCL-derived 研究子集，不与完整排行榜横比。

选用依据：BFCL 基础论文发表于 ICML 2025，公开评估调用选择、参数及相关能力；适合检验“结构正确但调用意图错误”的现象，不足以证明 Orch 真实代码验收可靠。[正式论文](https://proceedings.mlr.press/v267/patil25a.html)、[官方数据说明](https://github.com/ShishirPatil/gorilla/blob/main/berkeley-function-call-leaderboard/bfcl_eval/data/README.md)

## 6. 运行流程与规模

### 6.1 先验收装置，不先烧 worker

1. 六个独立开发需求（代码/文档各 3），A/B/C 各生成 1 次，共 18 次；D 复用 C。确认后端受限开关真实生效，检查所有 gold/candidate、文件存在、命令可启动及解释器一致性。
2. 用开发 Q2/Schema/固定契约例子验证研究适配层；不修改生产冻结接口。准备 R0：模型、Schema、解释器、提示词、题库、检查文件、价格折算与分析规则摘要。
3. 正式 T2-local：24×3 个生成策略×3 次重复＝**216 次首稿生成**，独立会话。D 只重判 C。暂不运行 worker，不让代码实现随机性污染契约比较。
4. 每份契约对六份相同候选回放，四种接纳策略总计 **24×3×4×6＝1,728 个决策**；D 的 432 个决策与 C 共享输出，不能当成额外独立生成数据。gold/候选评分不反馈给模型。
5. Q2-small 200 标准实例与 V2-mini 60 逻辑例单独报告；J2-small 做 120 次生成，验证结构效应能否外部复现。
6. 如基础结果可解释，再启动预先登记的修补子实验或 BFCL 复验；不因 p 值接近显著而追加题。

### 6.2 有限修补子实验（预注册选做）

预选 8 个正式需求，代码/文档各 4；各重复 3 次。A/B/C 首稿各自遇本组可观察错误时最多一次内容修补，D 从对应 C 首稿分叉，收到额外静态诊断后至多一次修补。若首稿通过则不凭空增加调用。

首稿可复用主试验，但必须在主试验开始前指定这 8 题；不使用人工 gold、候选错误标签或隐藏测试的反馈。A/C 原路径与 D 静态拒绝策略看到的诊断差异正是干预，须保存诊断文本。每组最多两次生成，与 exp_runner.plan_for 当前计数一致，但不是直接拿旧脚本改配置就能跑。

最多额外 8×3×4＝96 次修补生成，实际按失败情况减少。C/D 的分叉修补输出此时不再相同，各自计费用。D 的首稿费用作每次独立部署的反事实全额成本计入，与 C 共享一次实际付款的账单分开，不能向账户账单虚增付款。

### 6.3 顺序与统一配置

种子 20261111；先按任务家族、代码/文档分块，块内平衡 A/B/C 顺序；D 跟对应 C 同输出重判。默认 240 秒/次生成；最大输出上限由开发集最大 AST 验证后统一冻结。每个候选从独立相同快照评分，测试结果、模型 judge 证据和输出分别归档。

全部试验由用户后续手动运行；本次只设计。正式失败保留，退出码 2/找不到工具记 launch_error，检查已运行返回预期不符记 assertion_failed，Schema 拒绝、静态拒绝、judge_error、unsupported 各有状态。解析失败也不能靠手工修补后记作首稿通过。

## 7. 指标与统计口径

### 7.1 三层指标

| 层 | 指标 | 分母与解释 |
|---|---|---|
| 格式/表达 | 首稿结构有效率；可启动率；错误分类 | 所有分配的 trial 为主分母；完整响应且支持子集的条件率另列 |
| 意图 | 关键约束全保留率；无依据新增/矛盾率；错对象/值/组合率 | 以输入中的明确与合法推导信息为 gold；不是 AST 字符串 exact match |
| 实现判别 | 两正确均接纳且四错误均拒绝的比例；FAR；FRR | 以全部 trial/候选计，拒绝生成或语法失败也保留；另报有效契约条件率 |
| 资源 | 实际内容重写次数；生成/解析/静态/执行/judge 耗时；分项 token；影子费用 | 失败和修补都计入；不只统计成功者 |

主终点：**完整判别成功率**，每份契约同时接纳两份正确产物并拒绝四份错误产物才记 1；格式错误、弃答或不支持为 0。它不奖励“全部拒绝”。

FAR＝被接纳的错误产物/所有错误产物；FRR＝未接纳的正确产物/所有正确产物。D 只多拒绝时 FAR 可能机械下降，因此同时给 FRR、覆盖和完整判别。C/D 首稿意图保真率应相同；如报告 D 更高，须明确那是“被保留契约上的条件精度”，不是总体生成质量提高。

E014 仅为 A 的旧规则诊断，不把 AST 组 E014=0 作为跨组主结论；跨组比较用结构错误、引用错误、不可执行、意图错误等统一 taxonomy。E007 固定任务外壳规则仍可能存在，AST 判据本身不保证消除 E007。

### 7.2 预注册对比和样本限制

确认优先级：①B→C 的全部 trial 结构有效率差；②C→D 的完整判别成功率差。两项主检验 Holm 校正、双侧总体 α=0.05。A→B、A→C/D、代码/文档交互、费用和修补结果为次要估计，明确标记。

每个任务内对 3 次重复先平均；任务/来源家族整体配对重采样，保留全部策略和六候选关系，bootstrap 10,000 次，报告百分点差及 95% 区间。不能把 1,728 个决策当 1,728 个独立需求。D 重判无生成随机性但仍有候选家族相关性。全通过/零错误时加报告任务级保守上界，不用退化区间证明“错误绝对为零”。

24 家族定位为机制估计试验，不预先承诺显著性或跨模型结论。若需要确认 15 个百分点的实用差异，在独立预实验后模拟实际任务内相关及校正功效，事前从 24/48/72 家族选规模；不足则保留估计研究，不在正式结果出来后补样本追显著。第二个模型作为独立复现阶段，不把模型差异塞进解码主对比。

## 8. 预期结果与依据（不是已取得的结果）

| 预期 | 对比/可能结果 | 依据 | 证据强度与反例 |
|---|---|---|---|
| 受限解码最直接改善格式 | C 比 B 更少缺字段、非法结构；完整、受支持输出可能接近全有效 | 语法约束机制；JSONSchemaBench 分开研究有效性与覆盖 | 强方向依据；超时/截断/不支持使全请求远低于理论上限，且 B 本来接近满分时增益很小 |
| 格式有效不会自动带来意图正确 | C 仍出现合法但错 check_ref、错阈值、漏约束、ALL/ANY 错 | Schema 只能保证其编码的条件；StructureBench 分离结构与语义评价并发现语义改善非必然 | 强边界依据，但其小模型结果不能直接量化当前模型的降幅 |
| 静态检查减少特定错误的错误执行 | D 拦不存在引用、类型/操作错误和明确不可启动检查；C/D 原始意图保真不变 | 当前 E43 的找不到 checks 案例；类型/引用检查的确定性定义 | 中强机制依据；若冻结 Schema/生成已杜绝这些错误，D 几乎无增益；静态合法却意图错误仍漏检 |
| E014 型表达返工可能减少 | B/C 用明确操作字段减少靠谓词措辞过审的需要 | 当前 contract.is_decidable 与 E40 的规则匹配案例 | 中等本地线索，尚非干净因果证据；AST 可能引入新的字段/引用错，E007 仍可能存在 |
| 可靠契约的总成本可能下降 | 有较多规则型重写时，B/C 或 D 修补策略可能省整轮规划 | E40 记录规划调用/计划形态会显著改变费用；少一次调用的机制 | 待检验；历史数据同时改 prompt 与拆法，不能照搬其倍数；结构/静态开销和 judge 成本会抵消收益 |
| 缺陷检出未必整体大幅提高 | 可能只见结构变好，而完整判别率改善小；也可能静态约束确有增益 | 合法但弱/遗漏的判据仍接纳错误实现；需要本试验 gold 候选验证 | 核心研究未知；若只格式提升，结论限定为接口可靠性，而非语义验证突破 |

**不预报具体通过率和降本百分比。** 当前没有同模型 A/B/C 的干净预实验，不能把“99%”“返工减少 80%”伪装成文献支持的 Orch 预测。可给实用判定阈值，例如首稿结构有效率提升 10pp 或完整判别提升 15pp，但它们是研究者选定的最小关注效应，不是预计观测值。

成本可证伪的条件：设固定格式/检查额外成本为 K，每次被避免的修补平均成本为 R，被避免修补的期望次数为 Δr，则总生成链成本下降的必要账目关系近似为 Δr×R>K。若还替换 judge 或输出长度变化，要分别加减其成本，不能全部记成语法收益。所有量来自本试验，不能用历史 token 价格混算。

### 9.1 当前仓库的一手线索

- orch/contract.py 的 is_decidable：显式包含 _CMD、_PREDICATE 与 _ANCHOR；说明旧规则测量的是指定模式的可识别性，不是需求语义的完整正确性。
- orch/verifier.py 的 verify_task/judge：命令与断言走不同评分路径，说明必须控制评分者和模型调用费用。
- docs/实验日志.md E40：分号/谓词表达、prompt 和计划形态共同变化；适合提出假设，不足以单独估算 AST 的因果效应。
- docs/实验日志.md E43：真实检查文件缺失，说明运行能力/题库缺陷可能伪装成模型失败；D 的上下文检查应明确识别此类状态。
- scripts/exp_runner.py 的 plan_for：已有两次生成闭环和 token/时间记录，但不支持本设计的 AST/受限/配对重判，不能宣称当前脚本已经可直接执行实验二。

### 9.2 外部一手研究

1. [JSONSchemaBench，Geng 等，2025](https://arxiv.org/abs/2501.10868)，[全文](https://arxiv.org/html/2501.10868v3)：把效率、特性覆盖和输出质量分开评估，支持本方案不把格式通过率等同任务正确率。不能从其特定解码器结果直接推断本机费用或速度。
2. [StructureBench，IJCAI 2026 正式论文](https://ijcai.org/proceedings/2026/267)：比较提示生成和受限框架，报告结构有效与语义正确并不总同步；其研究覆盖端侧小模型，作为边界证据，不作为当前大模型的数值预测。
3. [BFCL，ICML 2025 / PMLR](https://proceedings.mlr.press/v267/patil25a.html)：公开研究函数/参数调用、组合与弃答，支持选为外部语义评价来源；不证明静态检查就能完全理解用户。
4. [JSON Schema Test Suite 官方项目](https://github.com/json-schema-org/JSON-Schema-Test-Suite)：提供规范测试的有效/无效实例标签；支持检查校验实现的标准符合性，不评价自然语言保真。

所有引用用于支持机制与设计选择，不替代本项目的实验结果。未以二手榜单、宣传页或历史小样本作为定量效果担保。

## 10. 日志与成功/失败结论

后续需要新增的研究日志：模型实际版本与解码开关；Schema/提示词/解释器摘要；原始输出和严格解析/兼容抽取状态；attempt/repair/transport_retry 分别计数；每条违规位置和检查层；check_ref 解析及命令是否启动；candidate/gold/constraint 对应；stdout/stderr、退出码与阶段耗时；judge 是否调用；缓存/输入/输出用量及影子价格版本；C/D 共享输出的 parent_generation_id 与成本归属。

解析器自动从代码块“捞 JSON”的成功率和原始严格格式成功率分别记；不能拿 B/C 的严格解析与 A 的人工兼容转换混称一个格式指标。诊断可以宽容，但首稿格式错误事实保留。

最终按证据选择结论：

- C 比 B 格式更稳、语义/完整判别没改善：形式化改善接口稳定性，未证明改善需求理解。
- D 减少 FAR，同时 FRR/弃答上升、完整判别无改善：更保守的筛选，存在覆盖代价，不能称全面更准。
- 完整判别提高且可靠契约成本降低：支持在当前任务/模型范围内部署该研究机制，再考虑冻结接口变更流程。
- B 本已格式满分，C 开销更大：当前基线无需受限解码；也可能仅 AST 表示或静态检查值得保留。
- 所有方式都漏掉相同关键需求：瓶颈在需求到检查的语义映射/测试覆盖，不是 JSON 形式；后续转向约束追踪，而不是继续把语法做复杂。

本次交付只有方案。后续实现研究适配、制作正式题库、下载公开集与执行均另行安排，保持生产冻结规则和旧实验数据不变。
