# 实验六　强制编排 · 规模阶梯（2026-11-11）

> 一句话：**只留一个自变量（编排 / 不编排），用强制编排消掉"模型自己选"的噪声，
> 看同一族任务在多大时编排才开始划算。**

## 零、先证明一件事：手工跑和 CLI 跑，结论一样

这一节是前提。如果"人来点"和"脚本调"本身就让结果不同，后面的所有数字都没法合并。

### 0.1 原理：三条差异，两条可消、一条必须控制

客户端和 CLI 调的是**同一个 `codex.exe`、同一个 `config.toml`、同一个模型与推理档**，
差别只在外面那层封装。封装带来的差异只有三处：

| 差异 | 影响什么 | 是否影响结论 | 处理 |
|---|---|---|---|
| **系统提示 / 脚手架长度** | 每轮输入的固定前缀长度 | **会影响比值**，需单独核对 | 两臂用同一驱动可减小差异，但不能假定自动抵消（见 0.1 更正） |
| **工作目录** | 文件定位 | 会影响（改错地方就白做） | 两边都固定到格子目录；错目录会被"补丁几乎为空"检出 |
| **工具可见性**（`orch` 在不在 PATH） | **行为**（会不会去编排） | **会，而且很大** | 必须机制化：A 臂跑前隐藏 shim |

关键在第一条。客户端与 CLI 的差异是**每轮输入的固定前缀差几十 K token**，它加在
每一条消息上，与"模型怎么解题"无关。所以：

> **更正（2026-11-12）：上面"自动抵消"的说法不成立。**
> 给两臂各加一个固定前缀 c 后，比值变成 `(D+c)/(A+c)`，一般**不等于** `D/A`；
> 只有当 c=0 或 D=A 时才相等。而且两臂的轮次数可能不同，前缀会被重复发送不同次数，
> 实际增量并不相同。因此：
>
> - 同一驱动只是**减小**差异，不能当作已消除；
> - 0.2 的"同一题补丁逐字节相同"只证明**那一题、那一轮**的解题过程一致，
>   不足以推广到所有题型、驱动和轮次；
> - 本实验的结论只对**同一 Codex CLI 驱动、同一价表、同一批合成题、n=3** 成立，
>   外推到其他客户端、模型或真实需求时，比值需重新测量。
>
> 实验的因变量是"成本比"和"质量"；前缀差异**会**进入成本比，不能据此说它不进结论。

### 0.2 实验：同一题、同一提示、同一模型，两种驱动各跑一次

A 臂（不编排），taskset-v1 的 b3，8 个单元：

| 指标 | 手工（客户端） | 机器（CLI） | 差 |
|---|---|---|---|
| 单元通过 | 8/8 | 8/8 | 0 |
| **补丁字节** | **4,672** | **4,672** | **逐字节相同** |
| H 输入 | 228,007 | 200,267 | **−12.2%** |
| H 输出 | 1,622 | 1,626 | +0.2% |
| 折算成本 | $0.0763 | $0.0724 | −5.1% |
| 墙钟 | 74s | 68s | −8.1% |

**怎么读这组数**：

1. **产出完全一致**——补丁逐字节相同，说明两者写出了同一份实现。
   这是"无影响"最硬的证据：实验判的是"补丁能不能过验收"，而补丁一样。
2. **输出 token 差 0.2%**——模型"想了多少"没变。
3. **输入 token 差 12%**——差的是前缀（系统提示长度），不是解题过程。
   折算成钱只差 5%，因为绝大部分输入是缓存命中（$0.1/百万）。
4. **墙钟差 8%**——在这个量级上与噪声无法区分。

### 0.3 这条结论的适用边界

| 成立 | 不成立 |
|---|---|
| 两臂**同一驱动**时，成本比与质量比可比 | **混用**驱动（A 手工、D 机器）时，A 的输入会被高估约 12% |
| 结论是"方向 / 比值"时 | 结论要精确到"绝对值差 5% 以内"时，12% 就不能忽略 |
| 工具可见性已被机制化控制 | 只靠"记得关技能"时——E22 里 A 臂自己派了 8 个 worker，成本 3.5 倍 |

所以本实验的硬规则：**一次跑批内，两臂同驱动；A 臂的 `orch` 由脚本隐藏，不靠人记得。**

## 一、为什么要把"路由"拿掉

前一版设计里混进了"路由臂"（系统自己判断该不该编排）。它引入了第三个变量：
**判断本身对不对**。于是同一个数字既可能是"机制没用"，也可能是"判断错了"，
两者无法分离。

去掉之后，问题变得可以被单变量回答：

> 给定任务 T，编排做 vs 不编排做，成本与质量差多少？这个差随 T 的规模怎么变？

## 二、为什么必须"强制"

E22 的实测：同一句原话（都含"你可以用 orch，用不用你判断"），

| 驱动 | 模型的选择 | 成本 |
|---|---|---|
| 客户端 | 不编排，48 秒自己做完 | $0.0557 |
| CLI | 编排，8 个 worker，428 秒 | $0.2969 |

**5.3 倍差距，只因为模型这次想不想用。** 这种方差下，任何"平均成本"都没有意义。

所以本实验把选择权从模型手里拿走：

| 臂 | 谁决定编排 | 怎么执行 |
|---|---|---|
| **A（不编排）** | 不编排，且 **orch 不可达** | 一次 Codex 会话从头做完；跑之前把 `~/bin/orch*` 改名，跑完恢复 |
| **D（强制编排）** | **由 harness 强制** | 先让 Codex 出一份 plan（`.exp-plan.json`，经校验）→ `orch dispatch` 派给 L 执行 |

两臂的原话**逐字相同**：都不提 orch，也不提"要不要编排"。差别只在执行通道。

> A 臂藏起 `orch` 是必须的：E22 里 A 臂只是没关技能，它就自己派了 8 个 worker，
> 成本从 $0.0724 涨到 $0.2531。这个条件不能靠"记得关"，必须机制化
> （`exp_lib.orch_hidden()`）。

## 三、阶梯怎么搭

同一族任务、**同一个单元内容**，只改单元数 N：

| 题 | N | 内容 |
|---|---|---|
| `sc01` | 1 | 给 `src/loader_01.py` 的 `fetch_all` 加超时重试（3 次上限，只重试 TimeoutError） |
| `sc02` | 2 | 同上，两个文件 |
| `sc04` | 4 | 同上，四个文件 |
| `sc08` | 8 | 同上，八个文件 |
| `sc16` | 16 | 同上，十六个文件 |

单元之间**互不依赖、写入集不重叠**（这是编排能并行的前提）。
生成器 `scripts/make_ladder.py`，双向自检：seed 通过 0/N、参考解通过 N/N。

为什么复用同一个单元而不是换题型：换了题型，N 的效应会和"题型变了"混在一起。

## 四、指标

| 指标 | 含义 | 为什么用它 |
|---|---|---|
| **D/A（金额）** | 两臂总成本之比 | 主指标。按 `config/prices.json` 折算，**不比 token**（跨模型不可比） |
| 每单元成本 | 成本 ÷ N | 看规模经济有没有出现 |
| 通过率 | `units_ok / N` | 质量不能掉，否则便宜也不算划算 |
| **H 额度比** | D 的 H 侧输入 ÷ A 的输入 | 订阅下真正稀缺的是额度，只拿 H 跟 H 比 |
| 墙钟 | 秒 | 体验指标 |

## 五、判定

**收益随规模上升**的判断标准：存在一个 N，使 `D/A(N) < 1` 且 `通过率(D) ≥ 通过率(A)`。

三种可能的结果，都有信息量：

| 结果 | 结论 |
|---|---|
| D/A 随 N 单调下降，在某个 N 穿过 1 | 编排有明确适用规模，交叉点就是"该开编排"的门槛 |
| D/A 一直 > 1 且不下降 | 编排在这个形态上没有规模经济——问题不在 N，在机制本身 |
| D/A 下降但通过率也下降 | 便宜是用质量换的，不能算收益 |

## 六、边界（写清楚，免得被过度解读）

1. **只覆盖同构批量**。跨文件新功能、修 bug、文档任务不在这一轮。
2. **每格 1 次**。D 臂的计划质量有方差，单次只能看趋势，不能给区间。
3. **单元是"同样的活重复 N 次"**。真实需求里这种形态确实存在（批量改写、批量加校验），
   但不是全部——所以结论只能限定在这类任务上。
4. 金额是等价 API 单价折算，不是订阅实付。

## 七、怎么跑

```bash
python scripts/make_ladder.py --force --verify          # 建题 + 双向自检
python scripts/freeze_taskset.py check --tasks sc01,sc02,sc04,sc08,sc16
export DEEPSEEK_KEY=...
python scripts/exp_runner.py --arms A,D --tasks sc01,sc02,sc04,sc08,sc16 \
    --out runs/exp/ladder.jsonl
python scripts/report_ladder.py                          # 出曲线
```
