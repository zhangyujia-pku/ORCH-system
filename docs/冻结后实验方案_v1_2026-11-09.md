# Orch 冻结后实验方案 v1.1（公开测评集整合版）

编制日期：2026-11-09。状态：方案草案，尚未预注册、尚未执行。本文只规定后续研究工作，不修改工程实现，不表示所列实验能力已经存在。

本次修订：明确公开数据来源、分层抽样、派生标注和跨集去重；加强实验二的外部测评与 Orch 回放对应关系。仅更新本文；未下载数据、未建立实际样本清单、未修改代码。下文数量均为拟定抽样配额，尚未核实下载后候选池的可用数量；实际数据 revision、仓库名和 instance_id 在获准取数后的资格审查阶段填写，不虚构已抽到的任务。

## 1. 研究目标与优先级

三项实验形成“需求表达—契约编译—交付结果”的证据链。实验二按加强版设计，可独立作为核心研究；实验三验证工程价值；实验一解释输入因素。正式实验前均需完成预实验和研究配置冻结。

| 实验 | 研究问题 | 可支持的结论 | 不预先承诺的结论 |
|---|---|---|---|
| 一 | 信息充分度、冗余与指称方式如何影响规划？ | 指定模型、仓库和任务分布内的因果效应与边界 | 必然 U 形、单锚点普遍最优 |
| 二（重点） | 格式约束与语义约束分别能减少哪些契约错误，能否减少错误交付被接纳？ | 语法有效、语义保真、实现判别三个层次的增益与代价 | AST 自动消除需求歧义，Parser 自动证明实现正确 |
| 三 | 确定式编排与廉价执行模型分别怎样影响成本、时间和质量？ | 固定任务分布下的质量差距、成本比及并行收益 | 普遍四倍降本、全局帕累托最优、最优工程范式 |

已有 experiments/ 中的数据仅用于形成假设、估计预实验量级及追溯工程缺陷，不并入正式样本。既有 U 形、单锚点和四倍差价均作为探索性观察。不得为了显著性追加样本。

## 2. 冻结与启动条件

采用两次冻结：

1. **工程基线冻结 B0**：独立并行、依赖成果传递、失败恢复三个真实后端场景完成；固定整体验收、取消与恢复不误报成功。记录代码内容摘要、测试结果和环境。若目录不是 Git 仓库，先明确正式版本管理位置；当前工作区副本不能直接假定已有可用提交号。
2. **研究配置冻结 R0**：未来补齐实验适配器、日志和计费采集后，锁定其版本、任务集、模板、标注、提示词、随机化表及分析方案。所有实验臂共享相同 B0；研究适配层单独记录摘要。预实验允许修正，正式实验开始后不得静默修正。

启动门槛：

- 后端身份、模型版本或快照、CLI 版本、参数、工具权限均可追溯；不能锁定服务端模型时，明确“版本未知”，缩短配对时间窗，记录响应元数据，不宣称完全复现。
- 所有任务起始版本已验证，基线测试可运行；参考正确实现通过独立最终测试，预制缺陷实现确实被对应测试检出。
- E014、规划失败、超时、基础设施失败和不支持表达有不同状态；对照组也能留存同等粒度的证据。
- 实验二确认后端真正支持所需语法约束与 Schema 子集。仅提示词要求 JSON 不算受限解码；若不支持，实验二相关单元暂不启动，不能悄悄替换模型补齐组别。
- 实验三能取得逐请求用量或可归属账单；只有批次余额差时，只开展批次平均成本研究，不能报告单任务精确金额。
- 小规模日志演练通过：中断、失败、恢复、重跑各有证据，重复事件不会造成重复计数。

每次正式运行绑定 experiment_id、protocol_version、trial_id、arm、case_id、replicate、block_id、B0/R0 摘要。冻结登记表不得留空模型、价格、任务起点和预算字段。

## 3. 共用任务集与实验纪律

### 3.1 任务来源及划分

任务优先取自公开测评集已有的真实仓库、问题、版本和测试，不再从零手写全部任务。各实验分别选仓库，不强求三项实验共享同一组 4 仓库。仓库以可复现构建、可离线评分、任务配额充足为准，优先 Python，覆盖至少两类实际应用或库维护场景。CLI、HTTP/API、数据处理、持久化作为覆盖标签记录，不在没有候选数据时假定能各占一个仓库。现有 demo/tasks_app 只用于调试或预实验，不作为唯一正式仓库。

任务从真实缺陷、功能请求或维护需求改编，避免仅替换常量和格式。每个任务有独立起点和参考实现；同一问题的改写、同源任务变体不能分散到预实验与正式集。预实验不与正式实验共享基础任务。

### 3.1.2 统一抽样与去重规则

取数后先生成仅依赖来源元数据和人工资格标签的候选表。每项来源固定 dataset_revision/commit、split、获取日期、原始 ID 和内容摘要；Live 不使用随时间变化的 latest 别名。所有配额、替补顺序在任何被测模型输出产生前冻结。

抽样流程：

1. 先排查同 issue/PR、相同基线+等价补丁、相同 bug 生成母本、同测试故障家族以及明显同义任务。保留 canonical_family_id，跨 Verified/Live/SWE-smith 同源任务只占一个来源位置。
2. 排除无法重建、缺必要材料、需要未授权外部服务、测试不稳定、需求与测试存在未解决矛盾的任务。每个排除有原因和证据；不能因某模型做不好而排除。参考实现、测试答案只向资格审查者开放，不进入模型可见上下文。
3. 按各实验配额建立仓库/来源/任务类型 strata，候选按 canonical ID 排序后用种子 20261109 随机排列。正式及扩样候选、预实验、开发调试、备用队列均以整个 family 分配，不随机拆单条变体。
4. 仓库按合格容量筛选后，以固定随机序选择可满足配额的组合；领域标签仅作预定覆盖约束，不按模型分数选仓库。配额不够时记录缺口，在 R0 前修订数量或仓库组合；不拿重复题补齐，不静默挪用其他来源。
5. R0 前资格失败按同层备用队列补位；R0 后按第 9 节处理。不能看正式结果后再替换“太难”的题。将各来源总量、筛除量、入选量画成流转表。

同一公开来源并不意味着无训练污染。记录原问题日期、首次公开/基准发布日期及模型训练截止是否已知；将 Verified 与 Live 分开报告，不声称“新任务必定未被训练”。代码改写、换变量名和翻译也不能消除既有污染。

### 3.2 每个任务必须准备的材料

- 任务说明、起点版本、允许工具、公开上下文与可修改范围。
- 原子约束清单：constraint_id、原文证据、对象、动作、输入条件、期望结果、必须保持的行为、重要性、是否需要澄清。
- 约束来源分类：用户明说、合法推导、未支持推断。不可把“研究者希望如此”当成用户明说。
- 参考实现和独立最终测试。隐藏测试及答案存于模型不可见的位置，不能只靠“请勿读取”隔离；测试摘要预先冻结。
- 公开检查与隐藏评测分开：公开部分可用于反馈；隐藏部分运行结束后仅评分，不返回可用于继续修复的信息。
- 任务难度、文件范围和依赖形状由两名标注者在运行前独立标注，分歧裁决后锁定。模型输出匿名乱序交给标注者。

### 3.3 随机化与运行规则

随机种子固定为 20261109；生成并保存实际随机化清单。种子控制顺序，不保证远端模型确定性。每个任务各臂配对运行，按仓库和任务类型分块，块内随机顺序并平衡各臂先后位置；不得先跑完一个臂再跑另一个臂。

每个正式条件默认重复 3 次，每次独立会话、工作目录与运行 ID；不继承上一臂的代码、对话、计划或失败提示。缓存使用一致的真实使用策略，不通过只给某臂加随机前缀消除缓存。缓存命中单独记录；可控时另做独立冷启动敏感性分析。

所有任务从相同起点恢复。实验过程中不得人工纠正某一臂。一般任务不允许临时人工澄清；实验二边界集考察是否正确请求澄清，不实际补充信息继续生成。

## 4. 实验一：需求文本与规划返工

### 4.1 分组

三个子实验独立分析，不直接做 5×3×2 的机械全因子设计。

**E1-A 信息充分度，5 条件。** 每任务构造：L1 仅目标；L2 目标+输入输出；L3 再加边界条件；L4 再加保持约束；L5 再加验收细节。所有等级保持一个相同的显式定位锚点、同一目标行为，不额外增加功能。等级以约束清单标注的可用信息为准，不按字数分级。“极简/仅目标”不另立难以区分的两档。

解释限制：该子实验测增加任务信息的总效应，不能把 L5 更差直接解释成注意力受干扰。对低等级不惩罚未提供且无法推导的隐含要求；额外报告其与完整任务目标之间的缺口，但不把该缺口算成曲解。

**E1-B 等信息冗余，3 条件。** R1 简洁、R2 解释性复述、R3 多次重复解释。三组原子约束、实体、数字、验收要求完全相同；优先用普通说明扩写，不增加实体提及次数。目标长度比约 1:1.5:2，实际字数和 token 数记录。若无法保持相同锚点提及次数，该条重写后再入库。两名标注者确认信息等价。U 形只在该子实验作为探索性形状检验，不能因三个点有高低便声称存在稳定最优点。

**E1-C 定位锚点与回指，5 条件。** A0 无显式代码定位名；A1-R 一个唯一定位名、重复实体；A1-P 同一实体后续改用代词；A2-R 两个定位名、重复实体；A2-P 两个定位名、后续改用无歧义代词。两个定位名必须指向同一行为范围，例如文件名+其中目标函数名，不能从单文件改为新增第二个改动目标。锚点数定义为不同代码定位项数量，提及次数另记；数字阈值、测试命令固定，不能混计为该自变量。

A0 仍保留自然语言业务对象，避免把任务本身删掉。A0 不参与回指风格对比。回指效应只在 A1/A2 的 2×2 子集中估计。若“重复/代词”无法无歧义构造，该任务在所有相应条件中整体替换，不能只删除难条件。

24 任务×(5+3+5)条件×3 重复＝936 次规划运行。即便不同子实验有相似文本，也独立运行，不复用同一随机输出。规划最多 3 次调用尝试；同一预选模型承担初版与修补，单次 provider 调用超时 240 秒，整个 trial 最多 780 秒，不运行 worker，不混入廉价模型修补。provider 内部的全部计费请求仍须记录。

### 4.2 指标

主指标：**首稿联合合格率**＝第一次输出同时通过冻结校验，且独立标注无关键需求遗漏、矛盾或无依据的关键新增约束的比例。格式通过与语义通过同时报告。

次指标：首稿 E014 率、首稿任意错误码率、实际重写次数、三次内最终联合合格率、各阶段耗时、调用量、每次生成判据数及任务数。首稿 E014 率按 trial 计：首稿出现至少一次 E014/trial 总数；单判据 E014 率另按判据数计算，不混用。

独立语义评分针对该条件实际提供的信息与公开仓库上下文，不把完整高详细度需求偷偷作为低详细度判分标准。对未定细节允许保留未定或请求澄清；无依据地指定关键行为记为新增约束。

“实际重写”只计初稿之后真正发起的内容修补生成，三次均失败为 2 次重写；拒绝次数为 3，不能写成 3 次重写。provider 故障后的传输重试不是内容重写。零输出的故障状态保留，不伪造一份失败首稿。

### 4.3 分析

预先指定三项主对比：E1-A 的 L5−L1；E1-B 的 R3−R1；E1-C 的 A1-R−A0。以任务为聚类单位，重复内先平均，再等权汇总任务；报告百分点差及任务聚类 bootstrap 95% 区间。三项检验做 Holm 校正，双侧总体 α=0.05。

完整等级曲线、A2-R−A1-R、回指效应及交互作为次要分析。可辅以含任务随机截距、仓库固定效应的 logistic 模型；不稳定或完全分离时以配对估计和聚类区间为准。冗余曲线二次项仅作探索，不用其单个 p 值证明 U 形。重写次数同时画成功/耗尽分布，不只比较成功样本均值。未完成的耗时按截止时间截尾，报告限定时间内成功率和限制平均完成时间。

### 4.4 公开来源、抽样和新增标注

**主集选 Verified 派生任务。** 按第 3 节先选 3 个合格仓库，每仓库抽 8 个正式基础任务。每仓库按主标签分为输入/边界行为、结果/输出行为、回归/保持约束、对象定位相关行为，各 2 个；同一个 issue 只能归一个主标签。资格条件是一个可明确描述的主要交付目标、能定位到同一行为范围内的文件与符号、有可重复测试，不以“容易被拆成很多任务”筛选。P1 的 6 题从未入选正式/扩样家族中另抽，3 仓库各 2 题。

保留原始英文 issue 为来源证据，主试验使用经双人核对的一套中文需求。先制作忠实的完整中文版本，再生成第 4.1 节 13 个条件；不在不同条件混用英文原文和中文翻译。主要效应只解释中文受控需求下的结果，语言泛化另做研究。命令/符号本身保持原样；L5 的验收细节不能引入第二个不同定位锚点，必要的阈值与业务字面值不计入“代码定位锚点”。

每个基础任务需补：原文到中文的句段对齐；原子约束及出现等级；13 条文本的实体/唯一锚点/提及次数/回指对象；业务范围等价检查；字数与模型 token 数；哪些信息被有意删去、哪些仅被复述；每个条件可合理推导的结论和必须澄清的细节。两名标注者逐条件核对，不把来源 gold patch 的实现细节补进需求。

**FollowBench 只用于设计与标注校准。** 从五类约束中各抽 4 个完整递增家族，共 20 个家族，保留所有可用等级及对应中英文对照（有明确配对 ID 才配对，不能擅自认定同义）。其家族不拆散，专用于训练标注者识别“增加一条约束”和“仅扩写”，不运行 Orch，不计入 24 个编码任务。五类及递增机制依据官方说明；实际各等级条数取数后登记，不能预设都是 5 条。相关例子不得作为正式被测模型的额外 few-shot。

**IFEval 为可选补充，默认不运行。** 若预算允许，在 R0 前登记启用：选 60 个可由原版检查器评分的 prompt，长度计数、关键词、结构格式、开头/结尾、大小写、语言六个主类各 10 个；多约束 prompt 按固定优先序归一个主类，不拆题。保留原 prompt 与检查器，模型 3 次重复共 180 次回答；只报告原版 strict/loose 指令级及 prompt 级分数，不与 Orch 合格率合并。数量不足需在 R0 前调整配额。它用于辅助判断一般指令遵循是否出现类似问题，不能替代 E1 的规划因果对照。

## 5. 实验二（加强版）：从格式约束到语义契约

### 5.1 核心问题与可证伪假设

H2-F：受限解码提高结构有效率，但不保证降低语义错误率。

H2-S：显式类型、引用绑定与静态语义检查，在相同表达范围内减少对象/参数/组合错误，并降低缺陷实现被错误接纳的概率。

H2-C：这些收益可能伴随生成开销、误拒绝和表达覆盖损失。若优势只来自拒绝更多需求、选择更弱判据或更容易的样本，则不支持整体改进。

实验二包含三层证据：**独立夹具测校验边界 → 同需求生成测编译质量 → 同实现候选回放测验收可靠性**。最后一层不调用 worker 生成代码，避免执行模型差异污染契约比较。

### 5.2 五臂设计：基线 + 2×2 因子

所有组使用同一模型快照、相同需求、仓库上下文、检查目录及操作说明。只替换契约表示、所需示例和指定解码开关；这些差异全部归档。基线本身的外层 tasks JSON 保持当前实现。

| 臂 | 判据表示 | 解码 | 校验/解释 |
|---|---|---|---|
| N | 当前半自然语言字符串 | 普通 | 当前冻结版正则规则+现有执行/模型判分路径 |
| W0 | 弱结构 AST | 普通 | Schema+基础解析与执行 |
| W1 | 同 W0 | 真正受限解码 | 同 W0 |
| S0 | 强类型 AST | 普通 | Schema+类型/引用/操作兼容性检查+确定式解释 |
| S1 | 同 S0 | 真正受限解码 | 同 S0 |

W 与 S 的外层任务字段保持一致。W0/W1 相对 S0/S1 具有相同核心操作表达能力，但 S 明确参数类型、对象注册与允许的操作组合；不能通过给 S 更好的需求提示或额外测试知识制造优势。

建议核心操作限定为：运行已登记检查并比退出码/输出、文件存在、文件文本包含、符号存在、AND/OR/NOT。W 可用原始字符串表示路径/命令/期望；S 使用显式对象引用、类型和检查 ID，并校验引用存在、类型匹配、作用域合法、操作支持。两者最终映射到同一个确定式执行后端。N 获得完全相同的检查目录和对象说明。

S 中的静态检查不声称证明“选中的检查就是用户想要的检查”；选错合法检查、写错合法阈值仍由独立语义评分和缺陷回放发现。W 的自由命令也受与其他臂相同的执行权限约束。登记检查 ID 只是稳定引用，不能把正确答案只提供给 S。

所有组允许显式返回 needs_clarification 或 unsupported，格式按各组契约规定。该状态不能计作成功生成契约；单列是否应当弃答以及弃答是否正确。

**形式语义子集（增加可机械核对的证据）。** 从 core 中预先选 12 个需求，每仓库 3 个，限定为至多 8 个已登记原子布尔谓词及 AND/OR/NOT 组合。定义表达式的指称语义：原子谓词取冻结观察值，AND/OR/NOT 按布尔代数求值，未知引用和不支持操作返回显式错误，不自动转 PASS/FAIL。gold 公式由两名标注者根据需求独立构造并裁决，模型不可见。

对可无歧义规范化到该子集的输出，枚举至多 2^8 个逻辑赋值，检查生成公式与 gold 公式的命题等价性，保留导致不同判定的赋值作为反例。N 的规范化由盲评人工完成并保留原文对应关系，不用 LLM 自动翻译替它修正语义；无法规范化单列。AST 的类型/引用检查和解释器在相同真值向量上验证结果一致，并验证保义变换、NOT 双重否定及 AND/OR 组合的性质。

该子集给出的是有限命题语义下的等价性证据。若原子检查彼此相关，部分赋值可能在真实代码中不可实现，须标注这些反例为逻辑反例，不能冒充真实缺陷实现；真实行为证据仍以第 5.5 节回放为准。它不证明自然语言被正确标注、不证明原子检查完备，也不证明任意程序满足需求。结果单列“可规范化覆盖率、命题等价率、逻辑反例类型”，不与整个任务集的端到端成功率混算。

### 5.3 第一层：独立校验器夹具 V2

构造 240 个逻辑夹具，每个保留一个基础意图，生成 N/W/S 的语义对应表示；W0/W1 共用 W 校验器，S0/S1 共用 S 校验器，不重复算独立样本。类型分布固定：

| 类别 | 数量 | 例子 | 应检查的层次 |
|---|---:|---|---|
| 正确契约 | 60 | 有效对象、期望与组合，包括边界和合法变体 | 误拒绝 |
| 格式/Schema 错误 | 30 | 缺字段、类型错误、非法操作 | 结构识别；只在对应表示可定义时比较 |
| 引用/类型/能力错误 | 30 | 不存在的检查、对象类型不匹配、不支持运算 | 静态语义与可执行性 |
| 意图偏移 | 60 | 合法但错误的对象/阈值/检查；漏关键约束；AND 错成 OR | 对需求的语义保真；Parser 可能合理放行 |
| 空洞或削弱判据 | 30 | 永真式、仅检查无关输出、把必须项改成可选 | 缺陷检出与空洞性 |
| 超出表达范围 | 30 | 语言没有操作可表达的要求 | 正确报告 unsupported，而非伪成功 |

每个夹具分别标注 syntax_valid、static_semantics_valid、intent_faithful、executable、in_language。五个标签不可合并成一个“正确”。仅能检查语法的 Parser 放行格式正确但意图错误的契约，不算 Parser 语法误判；应计入整条验证链的语义漏检。

两名标注者独立评分，给出逐约束证据和裁决。各表示不可构造等价夹具时标记 not_comparable，保留并报告覆盖缺口，不把缺失当正确，也不从总分中悄悄删掉。该层不使用 LLM 挑选或修改失败例子，不依赖生成结果是否出错。

### 5.4 第二层：同需求契约生成

T2-core 48 条+T2-boundary 24 条，共 72×5 臂×3 重复＝1,080 次首稿生成。主分析只看首稿，不引入修补机会差异。每次生成超时 240 秒、相同最大输出 token 设置（预实验后登记为统一值），完成后仅作验证与评分。

core 每仓库的 12 条按四类各 3 条配置：命令/输出期望、文件/符号对象定位、数值或文本边界、组合与保持约束。类别允许共享操作，但主标签在运行前锁定；其中选择满足上文条件的 3 条进入形式语义子集，避免运行后只挑容易证明的输出。

另取预先分层抽样的 12 个 core 任务做有限修补副实验：5 臂×3 重复，最多 3 次生成，240 秒/次、780 秒/trial。各组返回同一错误分类体系的真实诊断，不额外泄露隐藏约束。首稿试验与修补试验使用独立会话，不能把已经看过判分的首稿续跑成新的独立样本。

语义评分：对输入中明确或合法推导的原子约束，计算关键约束全保留率、约束召回率、生成约束精确率、关键矛盾率、关键无依据新增率。多个 AST 等价表达均可正确，不能只用字符串 exact match。两名标注者盲评全部正式输出，先独立后裁决；记录二元 Cohen's κ 与原始一致率，保留分歧标签。

边界集分别报告：信息不足时正确澄清率、无依据猜测率；语言范围外正确 unsupported 率、伪可执行率。core 与 boundary 不混成一个“准确率”；始终同时展示成功处理覆盖率和选择性正确率，防止靠大量弃答提升分数。

### 5.5 第三层：正确/缺陷实现回放（关键加强项）

每个 core 需求预制 6 个冻结实现候选：2 个不同但都满足需求的正确实现，4 个定向缺陷实现。四种缺陷分别覆盖关键行为缺失、边界错误、旧行为回归、对象/交互组合错误。正确实现必须有合理结构差异，避免判据只识别参考补丁。每个缺陷有最小故障证据和隐藏测试对应关系；对单任务无法构造的缺陷类型整体换题，不临时挑最容易的缺陷。

将第二层每份生成契约原样用于相同 6 个候选，不让生成模型看候选补丁。48×5×3×6＝4,320 个契约—实现评估对。执行顺序随机化并从同一候选快照启动；冻结已有 diff 展示方式，模型判分也不得看隐藏答案。N 的 judge 调用与费用纳入成本；W/S 的执行时间及静态检查开销也记录。评估无副作用条件下允许复用相同确定式命令结果，但复用规则须统一、留证，并另报不复用的估算成本。

主要终点：

- **缺陷误接纳率 FAR**：标为“通过”的缺陷候选数/全部缺陷候选数。
- **正确实现误拒绝率 FRR**：未通过的正确候选数/全部正确候选数，另分契约无效、拒绝生成、判据误拒绝、执行故障。
- **配对判别成功率**：同一生成契约同时接纳两份正确实现并拒绝四份缺陷实现的比例；无有效契约或弃答为失败。该指标阻止“全部拒绝”获得低 FAR 的表面优势。
- 同时报告条件指标：仅有效可执行契约上的 FAR/FRR，以及以全部 trial 为分母的总体指标。不能只报告过滤无效输出后的优选结果。

这些结果只代表对预制缺陷集的检出能力，不代表证明任意代码正确，也不把 4 个缺陷当成 4 个独立任务。

### 5.6 变形测试与消融

在 12 个 core 任务上提前构造两类变形，不从失败输出反向挑题：

1. 保义变换：一致重命名对象、等价换序、相同需求的无歧义改写；变换后的引用目录及实现同步更新，判断应保持一致。
2. 改义变换：只改变阈值、目标对象或 AND/OR，配套候选实现使真值确实翻转，检查契约和结果是否相应改变。

共 12×2 变形×5 臂×3 重复＝360 次附加生成；复用同层规则评分，报告保义稳定率和改义敏感率，不只检查 JSON 是否变化。

离线消融在相同已生成 S1 输出上，依次关闭引用绑定、类型兼容、组合规则检查，重放 V2 与候选实现，记录被哪层首次阻断。它测检查层的拦截贡献，不能声称测到了“生成模型失去这些反馈后”的适应行为；后者需要新生成试验，暂不列入必做。

### 5.7 主对比与统计

预注册三个主问题：

1. 解码贡献：2×2 AST 子集中受限解码对首稿结构有效率的平均效应，报告 W1−W0、S1−S0，并检查交互。
2. 语义约束贡献：S1−W1 的配对判别成功率差。
3. 完整方案价值：S1−N 的配对判别成功率差。

三项主检验 Holm 校正，双侧 α=0.05。主要效应先在每任务内对重复和候选等权平均，再以任务聚类 bootstrap（10,000 次）估计 95% 区间。V2 以基础夹具家族聚类；T2 以需求任务聚类；不把共享契约的 6 个候选当独立观测。不稳定混合模型只作补充，不替代任务级结果。

结构有效率、语义保真率、FAR、FRR、覆盖率、token、金额及生成/解析/静态检查/执行/judge 耗时均分开报告。另列“结构有效但语义错误”占比与绝对数，区分错误是否从格式层迁移到了语义层。

若 S1 判别率提升但覆盖下降，结论为有条件的可靠性—覆盖权衡；若仅结构有效率提高而 FAR/判别率不改善，结论只能是格式稳定性提升。支持 H2-S 需要独立语义或实现判别证据，E014 接近零不能单独作为支持。

### 5.8 公开测评集整合：三个外部模块与一个 Orch 主集

外部模块与 Orch 主集独立报告。J2 的单位是 Schema，Q2 的单位是 schema-data 测试实例，F2 的单位是工具需求家族，T2 的单位是编码需求；禁止把四者拼成一个准确率。V2 仍是另设的 Orch 逻辑夹具集，不能用 Q2 的格式案例替代其语义错误案例。

#### E2-Q：官方 Test Suite 校验实现检查（启动门槛）

从固定版本 [JSON Schema Test Suite](https://github.com/json-schema-org/JSON-Schema-Test-Suite) 中选定同一 draft，默认 2020-12。抽 400 个带官方 valid 标签的实例，有效/无效各 200。按主特性分四层：标量类型/数值/枚举、对象字段/required/额外属性、数组/元素/长度、组合逻辑/引用；每层 100 个，正负各 50。多特性按“组合引用→对象→数组→标量”的顺序归主层。限制单个 schema 家族最多 10 个实例，且同一家族的正负例一起保留在同一数据用途分区。

抽样只在官方合法 Schema 对实例的 valid/invalid 判定中进行，不擅自把 Schema 本身非法与实例非法混淆。远程引用使用冻结本地资源；optional format、网络依赖等测试的适用性单列。解码后端未支持的特性记 unsupported，不能当成校验正确；若所选 DSL 必需特性不支持则相关主实验不能启动。若工具明确只支持另一 draft，则预实验时统一改定 draft、记录理由并重新锁定 Q2/J2；不能将不同 draft 的结果混算。

保留官方 expected_valid，不重打 gold 标签；新增 schema 家族、draft、主特性、required_by_DSL、后端 declared_supported、actual_status、执行错误和耗时。已有官方标签与实现结果冲突时记录并调查，不能为了让实现通过而改标签。

Q2 不调用生成模型，验证各 W/S Schema 校验适配是否遵守其宣称支持的规范。N 的自然语言规则不接受通用 Schema 实例，因此不参与这一分数；不给 N 硬造一个 0 分。必要特性上的错误为研究装置故障，须先修好再冻结 R0。

#### E2-J：JSONSchemaBench 结构生成外部集

从固定 revision 的 [JSONSchemaBench](https://github.com/epfl-dlab/jsonschemabench) 抽 200 个不同 Schema，四个主特性层各 50，分类优先序同 Q2。先按规范化 Schema 及引用闭包摘要去重，再检查与 Q2、开发样例的同源关系。尽量覆盖多个原始来源，每个主层内单一来源占比不超过 50%；若合格候选不够，在 R0 前明示修订而不是临时补容易题。

复杂度另标字段数、嵌套深度、组合/引用/递归情况，报告分层结果，不声称四个层具有相同难度。对 draft 和实际解码支持做独立资格标注；采样后遇到后端不支持的 Schema 仍保留在覆盖率分母，不能只测已经成功编译的 Schema。

每个 Schema 给模型同一中性任务“生成一个满足此 Schema 的实例”，只比较同一模型普通生成与真正受限解码，200×2×3＝1,200 次生成；240 秒/次，统一输出上限在预实验后锁定。校验用通过 Q2 的独立标准校验器，而非用解码器的“成功”标志作 gold。支持率、全部样本的有效产出率、已支持样本上的有效率、非空/退化输出特征、token/费用/时长分别报告。空对象若符合 Schema 应算结构有效，同时标记其信息量，不能主观改成无效。

新增标注：语法特性和复杂度、引用闭包、draft、所需资源、可满足性问题、解码编译/运行状态、独立校验结果。J2 无统一自然语言意图 gold，不评“需求语义正确率”，也不套 N/W/S 五臂。它只能给形式生成能力和覆盖的外部证据。

#### E2-F：BFCL 外部语义与弃答集（重点）

选固定 BFCL 版本的单轮数据类别，默认只保留本地可解析、无需网络的 Python 函数规格。按官方类别 simple、multiple、parallel、parallel-multiple、irrelevance 各抽 12 个，共 60 个基础输入/家族；multiple 指有多个候选函数，不等同于一定需要多个调用。按函数规格族分组，近似重复问法不得跨开发/正式；具体类别文件名以冻结版本实际元数据为准。

在抽中的 48 个非 irrelevance 基础输入中另选两个不相交的 12 家族集合，人工构造：

- 12 个 missing-parameter 变体：删除一个必需、无默认值、不能从剩余上下文推得的参数值；gold 为请求该参数澄清。
- 12 个 missing-function 变体：移除完成需求不可替代的函数，确认其余函数无法组合替代；gold 为明确能力不足，不调用不存在函数。

得到 F2＝84 个输入、60 个独立来源家族。24 个变体属于本研究派生数据，不冒充 BFCL 原生单轮标签；与母题一起参与家族聚类。原生 irrelevance 也逐题审查为“不应调用当前工具”，不能自动把缺能力、缺信息、闲聊混成一种弃答。

**五臂如何公平适配。** 为 F2 定义独立的工具调用契约适配器，保留相同 N/W0/W1/S0/S1 因子：N 用受控半自然语言描述调用，W 用普通字段 AST，S 用显式工具/参数引用及类型；S 只得到公开函数文档中已有的信息。工具调用内容与 Orch 验收谓词是不同语义域，适配器单独编号和冻结，F2 结果不能宣称等同于原 Orch DSL 的实现验收能力。五臂获得完全相同的函数说明、参数、默认值和上下文，不提供正确函数 ID 列表或答案提示。

W/S 的两种表示均能表达所需调用及合法弃答，并映射到同一规范化调用序列。N 按冻结的机械转换规则规范化；无法机械转换时标为 unresolved，并由双人独立核对是否确实表达正确。人工核对结果单列为语义上界，不能作为运行时自动解析成功，也不能用 gold 修正原输出后再交评分器。静态检查器不得通过硬编码参考调用或把答案集合写进 Schema 来“消除语义错误”。

84×5×3＝1,260 次独立首稿生成；不做额外修补回路。保留原 BFCL 的函数/参数匹配规则与可接受答案集合，仅在公共可比较类别上评分；无原生可比标签的派生边界按新增 gold 评分。新增工具调用映射后命名为“BFCL-derived F2”，不称完整 BFCL 官方分数，不与排行榜横比。

**必须补的语义标注。** 每题记录需求原子槽位及原文证据、可接受工具/参数答案集合、默认值与合法省略、调用数、顺序/并行可交换性、额外调用是否改变意图、可替代工具、需澄清槽位或缺失能力、人工派生步骤及双人裁决。静态类型正确但工具/值选错必须记语义错误；不能因为调用可解析便给通过。

F2 主报：全部必需调用正确且无不允许额外调用的完整任务成功率、参数语义正确率、合法但错误的调用率、应弃答识别率、错误弃答率、自动可规范化覆盖率及成本。保留 positive/irrelevance/missing-parameter/missing-function 分层。函数/参数匹配只说明调用内容符合 gold，不能证明真实工具状态或副作用正确；有本地可执行状态测试时另报告 execution 子集，不把 AST 匹配称执行验证。

外部语义副假设预设为 S1−W1、S1−N 的完整任务成功率差；对家族等权聚类，positive 与三类边界分别报告，宏平均作为汇总。它不替代 T2 的 FAR/FRR，F2 没有真实缺陷实现时不得虚构 FAR。

### 5.9 Orch 主集如何利用公开代码与缺陷

**T2-core 来源配额。** 选择两个 SWE-smith 来源仓库各 12 个合格家族，共 24；另一个 Verified 仓库、一个 Live 仓库各 12 个，共 24。四仓库每个按第 5.4 节四类各 3 个。本配额把合成缺陷与真实 issue 分开，主结果按二者分别报告，并给出各占 50% 的预定宏平均。不能把合成任务说成全部来自真实用户请求。

SWE-smith 原始 bug、对应原本正确版本和已有测试可作为素材，但题面若由工具自动生成，要记录生成方式并经双人核对。对 Verified/Live，保留原 issue、基线、参考补丁及测试变更作为来源；先按 issue/公开仓库内容抽取需求，再由另一名审查者检查测试是否覆盖。需求作者不得只读补丁反推一道“按参考实现才对”的题。

**T2-boundary。** 四个已选仓库各再取 6 个不与 core/其他实验重合的来源家族，共 24；各仓库 3 个制成信息不足变体、3 个制成核心 DSL 无法表达的能力边界变体。双人确认信息不足不能靠仓库默认约定补全，能力边界相对五臂共同声明的操作集合定义。只给 S 不支持、却给 N/W 任意运行新脚本的能力不算公平边界。保留未修改原题、变体文本、编辑证据、预期响应、不能推得/不能表达的具体理由，声明这些是人工派生边界，不是原数据集自带标签。

**实现候选的来源与补齐。** 每个 core 家族仍需 2 正确+4 缺陷候选：公开的原正确版本或 gold 修复可提供一份正确候选；第二份须由非被测模型输出的独立实现或人工构造并审查。SWE-smith 原始破坏版本或 Verified/Live 原问题基线可提供一个缺陷候选，另外的定向变体按第 5.5 节补齐。现有基线不一定有完整未实现功能之外的局部版本，任何候选都须实测并审查；不能假定一个公开题天然拥有六份合格实现。

为每个候选补：candidate_id、parent_snapshot、patch_digest、来源 original/reference/independent/mutant、改动点、预期违背的 constraint_id、最小失败输入、实际输出、所杀死的隐藏测试、非目标行为是否保持、正确性裁决。等价 mutant、无法构建候选或不属于目标错误类型者在 R0 前排除并留痕，不在运行后根据哪种契约能杀死它来筛选。48 家族最终需要 288 份候选，真正的 gold 由独立需求审查和冻结测试共同建立，公开 patch 本身不等于绝对正确。

**V2 来源与构造。** 使用额外 60 个独立基础家族，SWE-smith/真实 issue 各 30，与 T1/T2/T3/预实验不重合。每家族先构造一份人工核实正确契约，共 60；再预先分配错误类型：15 家族各一格式错+一引用错，15 各一格式错+一意图偏移，15 各一引用错+一意图偏移，15 各两种不同意图偏移，合计格式 30、引用 30、意图偏移 60；另从 60 家族中按独立随机序各选 30 家族补一空洞判据和一范围外变体，共 30+30。总量保持第 5.3 节 240。范围外变体同时保留其输入变化，不把不可表达的需求伪装成原题固有属性。

对 N/W/S 制作等价表示时记录 translation_pair_id 和语义证据；无法等价表达的错误类型标 not_comparable 并报告，不能用“删除谓词”与“删除 JSON 逗号”等并不相同的缺陷作强配对。V2 研究构造的是模型以外的反例检出，Q2 研究官方 Schema 规范符合性，二者分开计分。

**桥接分析。** 将 J2/Q2 的错误类型、F2 的工具/参数错误、T2 的契约/实现错误映射到统一 error_taxonomy：结构、类型、引用、对象选择、值/阈值、遗漏、新增、组合、表达覆盖、运行故障。映射用于解释相同机制是否跨域重现，不把三个域的分数加总，也不依据外部集结果更换 T2 的确认性终点。

### 5.10 外部集统计与可选扩展

J2 按 Schema 家族聚类、按四个预定层等权估计普通/受限解码差；Q2 按官方 schema 家族聚类，分 supported/unsupported 及正负例报告，作为装置质量门槛。F2 按 60 个来源家族聚类，母题和 24 个边界变体始终一起重采样；各类别等权汇总，保留 raw 分母，不能把 84 条当 84 个独立需求。

E2-J 的有效产出率对比、F2 的 S1−W1 与 S1−N 三项外部副检验构成单独 Holm 家族；与第 5.7 节三个 Orch 主检验分开标注“外部支持证据”，不能选两家族中有利的 p 值作为同一个主结论。外部模块默认规模用于分层估计，不预先保证确认性功效。若需升为确认性研究，在正式数据产生前追加独立预实验、功效模拟及样本登记，不用正式结果滚动扩样。

可选的 BFCL 原生格式参考运行：对 60 个基础输入用官方工具调用格式生成，3 次重复共 180 次；只检验适配前后难度和评价的一致性，不替换 N，也不并入五臂效应。默认不运行。BIRD Mini-Dev、BFCL 多轮/在线工具类别本轮均不启用；它们会引入数据库、状态与控制流程的新因素，需要独立方案及预算。

## 6. 实验三：架构与模型的成本—质量比较

### 6.1 四臂

| 臂 | 规划与执行模型 | 架构 |
|---|---|---|
| E-H | 强模型端到端 | 单 agent，自主规划与执行，不启用 Orch 中间闸门 |
| E-L | 廉价模型端到端 | 同 E-H 外壳和工具，仅替换模型 |
| O-H | 强模型规划、强模型执行 | Orch，固定契约、静态校验、任务验收、整合与公开整体验收 |
| O-L | 强模型规划、廉价模型执行 | 同 O-H 的 Orch 配置，仅替换执行模型 |

O-H/O-L 的规划及所有规划修补均使用同一强模型；judge 若存在，所有 Orch 臂使用相同固定 judge，单独记账。主实验关闭模型接替、人工回答和失败后重规划，避免额外因素；保留相同的有限任务修复配置。异构接替与重规划留待后续实验。

四组收到相同需求、起点、公开检查及全局约束。Orch 会产生不同上下文拆分，这是被测架构的一部分。所有组最终在同一独立隐藏测试上评分；公开反馈可被用于修复，隐藏评测不参与回路。端到端也允许在同一总预算内自测和修复，不人为限制只能生成一次。

### 6.2 任务与资源

起始候选 60 个任务，Verified、Live 各 30，分别选择两个仓库各 15 个：每仓库独立单元、并行多文件、依赖链/扇入各 5 个。最终样本按同样比例扩充。每类型覆盖实际候选池具有的功能增量、缺陷修复和行为保持，记录分布，不假定原数据集三类等量。任务定义为一个用户级交付目标；不能把一条拆成更多子任务就获得更多成功数。

默认 3 次重复、Orch 最大并发 3；每 trial 墙钟上限 1,800 秒，全部模型请求合计最多 120 次，实际 API 费用上限 5 美元。计数包括模型内部工具循环、规划、修补、judge 和重试，不能只计 provider.complete 次数。预算边界由未来的统一研究适配层落实；达上限不发新请求，在途请求的结算超出部分如实记入，不宣称绝对美元熔断。

资源值可在 P3 后调整一次，但必须对四组采用同一规则、在正式实验前写入 R0。不能仅为某组增时或增加调用上限。默认配置下 60×4×3＝720 次完整运行，名义 API 预算上限 3,600 美元，不含已在途结算溢出和人工标注；这是上限，不是花费预测。

### 6.3 终点与计费

主质量终点：固定预算内通过所有关键需求、回归和完整性检查的任务比例。超时、预算耗尽、无法交付和规划拒绝均不算交付成功。给出每次重复成功率与按任务平均的成功率。

主成本终点：每成功交付成本＝该臂全部 trial 实际费用/该臂成功 trial 数；失败、修补和 judge 全部计入。零成功时为不可定义/无穷成本，不能记零。另报每次请求、trial 和任务的成本分布，以及规划/执行/验收份额。

费用优先使用可关联 request_id 的实际账单；否则用分项输入、缓存输入、输出、推理 token 和冻结价格计算“估算 API 成本”，与账单核对。不同提供商 token 字段可能重叠，按其定义避免重复计费。推理 token 不可得时记 unknown，不能当零。订阅额度不能伪装成零 API 成本；若强模型只能走订阅，单列额度/用量及估算价格，主张降本时说明口径限制。只可得到批次余额差时，按独占账户/项目与结算区间报告批次平均值和测量分辨率。

时间从 trial 启动、首次规划请求之前开始，到候选交付、失败或截止为止，包含架构自身的规划、建工作树、等待、验收、整合和恢复开销。统一外部调度队列、预下载依赖和研究用隐藏评分耗时另记，不混入交付延迟。报告中位数、P90、限制平均完成时间及超时率，不只统计成功任务。

次指标：隐藏子测试通过比例、修改规模、冻结 Linter 规则下新增问题数/修改代码量、复杂度变化；任务级拒绝、越界、冲突、因写集规则拒绝拆分、实际并发利用率。低合并冲突不能单独证明架构优越，须同时报告保守串行化的代价。

### 6.4 非劣效与并行副实验

首要比较 O-L 对 E-H：定义质量差 Δq＝p(O-L)−p(E-H)。非劣效界值预设为 −5 个百分点，单侧 α=0.025；只有任务聚类 95% 双侧区间下界严格大于 −0.05，才称质量非劣。该界值是研究者可接受损失，须在预注册中说明理由；不能事后根据结果改界。

仅在非劣效成立后检验主成本比：CPS(O-L)/CPS(E-H)，用任务聚类重采样联合计算分子分母，报告 95% 区间。成本比上界小于 1 才支持降本；只有上界小于 0.25 才支持“至少四倍降本”。两组差异不显著不等于质量持平；样本不足时明确写“无法确认非劣”。

E-H 对 O-H、O-H 对 O-L、E-L 对 O-L 为次要对比，报告效应区间，若作显著性主张则对该家族用 Holm 校正。所有结果按任务形状和仓库分层，不能把聚合结果外推为所有任务最优。

并行副实验：预先选 12 个有并行机会的正式任务，在 O-L 下比较并发度 1 与 3，各 3 次重复，共 72 次新运行。两边使用相同的预先冻结合法计划、模型和反馈预算，并发度是唯一差异；已有主实验运行不替代该副实验。主报 T1/T3 的逐任务加速比、总模型费用和质量差。执行阶段与包含固定规划成本的总时间分别报告，不拿 E-H 与 O-L 的耗时比充当并行加速比。

### 6.5 公开集抽样、原版评价与新增标注

默认选 Verified 的两个 Python 仓库、Live 固定 Python 快照的另外两个仓库，4 仓库各 15；避免同一仓库身份与两个来源混杂造成无法解释的合并结果，来源差异只作分层描述，不据此宣称新旧任务的因果差异。若共同仓库可用，可在预实验前改成来源×仓库交叉设计并重新锁定配额；不在主实验后切换。

每仓库三个依赖形状各 5 个，先由两名人工在不看被测模型规划的情况下标注：

- 独立单元：交付可由一个边界清楚的改动单元完成；
- 并行多文件：同一真实 issue 内有至少两个可独立开展、写集分离的改动单元；仅“涉及两个文件”不充分；
- 依赖链/扇入：存在明确接口或数据依赖，后一个单元需要前置成果；不能用 Planner 最后拆出的形状反向定义分层。

按资格、形状和可见需求筛选后随机抽样，不按强/弱模型已有成绩选题。若某仓库没有足够真实并行/链式任务，换至备用仓库组合或在 R0 前修改配额并标明“并行机会不足”；不得把几个无关 issue 拼成一个任务来制造并行收益。并行副实验从人工确认的并行候选层中按来源各 6 个、仓库各 3 个预抽，参考计划只给副实验使用，不泄露给四臂主试验。

保留原版 problem_statement、base_commit、参考 patch/test_patch 和官方评测配置摘要；主任务不主动做中文改写。数据中的 gold patch、测试补丁、官方 FAIL_TO_PASS/PASS_TO_PASS 或相应评分答案只能供隔离评测，不能随数据表整包注入 agent 工作区。四臂看到相同原题和原始仓库，最终候选都经同版本官方 harness 或逐项等价、已验证的适配器评分。

需要补的标注：真实任务类型、难度依据、依赖形状/人工 DAG、可并行的最小单元及写集、每个原子需求的公开证据、原版测试覆盖与缺口、受保护文件、外部服务依赖、已知不稳定测试及环境失败原因。人工 DAG 是分析标签，不作为某一实验臂的额外提示。Linter/复杂度若要作为评分，所有组使用同一冻结规则，不按仓库临时选宽松规则。

结果至少分三张表：①按来源分开的官方测试 resolved/未解决及成本；②额外需求/完整性审查后的 Orch 研究交付成功率；③按三种依赖形状分层的费用/延迟。附加测试须在 R0 前锁定并对所有组一致；用了附加测试的分数不可称为原版 SWE-bench 官方分数。报告明确这是按仓库/任务形状筛选的研究子集，不冒充完整排行榜成绩。

SWE-smith 不进入实验三默认主集，以免主成本结论主要建立在合成缺陷上；将来若启用，另立合成任务分层。Live/Windows 不在默认主集：即便本机为 Windows，也不能混合原生 Windows 与 Linux 容器耗时而不建分层。环境配置须遵守各官方 harness；当前未实际验证本机适配能力。

## 8. 预实验、样本量与停止规则

1. 先在 P1/P2/P3 做演练，核对任务可辨别性、DSL 覆盖、后端特性、全部日志和真实花费。P1/P3 按各自正式来源另取家族；P2 的 12 题按 core 的来源比例取 6 SWE-smith、3 Verified、3 Live，边界变体仅用于演练、不入正式集。外部模块另预留 8 个 J2 Schema、16 个 Q2 实例、5 个 BFCL 基础家族（五类别各 1）及其变体用于开发演练，全部与正式外部集按家族隔离。允许修复实验装置，但 P 集不进入正式结果。
2. 用预实验估计基线通过率、任务内相关、配对不一致率、单任务耗时/费用。只用这些量规划规模，不用正式样本滚动挑选有利终点。
3. 实验一以 24 独立任务为初始方案，实验二以 48 core 为初始方案；针对首稿合格率 15 个百分点差和配对判别成功率 15 个百分点差，分别用任务级模拟估算 80% 检验功效。模拟包括 3 次重复及实际多重校正。候选规模依次为 E1:24/36/48/72，E2-core:48/72/96/144，取首个达到目标且预算可承担的规模；仓库/来源等权保持，类型层不能整除时按冻结的最大余数规则分配并记录实际权重，附加集按清单在运行前固定。V2、boundary、外部模块不因主集扩样自动扩成新的独立任务；若改变它们的规模须同步更新 R0 与预算。
4. 实验三在真实质量相等、非劣效界 −0.05 的假设下，使用 P3 的配对与聚类结构模拟功效；候选规模 60/120/180/240，取首个达到 80% 且可承担的规模。若均不能达到，固定可承担规模为精度估计研究，撤下确认性非劣效主张，不改宽界值获得“成功”。
5. 用固定种子记录模拟方法、输入、结果及预算预测，完成预注册和 R0 后才运行正式集。达到预定样本即停止；不得以 p 值、成本优势出现或“结果快显著”决定停止。没有预算继续时作为提前终止研究如实报告。

## 9. 故障、缺失与排除

- 正式主表保留全部分配到实验臂的 trial。模型格式错、契约拒绝、写集阻断、超时、花完预算和候选不合格均是结果，不删除。
- 机器休眠、明确平台宕机、网络整体中断等外生事故有独立原因码。主分析保留为未成功交付，另报告排除已证实外生事故的敏感性结果。按事先规则补跑完整配对块一次，补跑标记 replacement，原记录保留；主表与补跑分析不得混合挑好结果。
- 仅响应慢、工具启动失败、权限不满足不能自动归类为外生；需证据区分系统配置缺陷、架构行为与外部事故。研究装置故障影响结论时暂停全部相关臂，先定位，不只重跑差的一臂。
- 冻结摘要变化、隐藏测试泄露、任务起点错误或模型身份切换时停止受影响块。修复后升研究版本，旧块保留并分层；不得拼成同版本确认性结果。
- 无法结算的费用标为缺失，给出覆盖率与可核对部分，不为未计费样本填零；关键费用缺失时不下精确降本结论。

编码主集按仓库内、任务家族成组重采样，保留每次重复及各臂配对关系。本文 bootstrap 默认 10,000 次、固定种子；每项编码主集只有 3–4 个仓库，区间主要反映这些仓库内任务的不确定性，不支持对任意仓库总体作统计外推。总体采用仓库等权、仓库内任务等权，失衡或缺失时不让任务较多的仓库支配结论。J2/Q2/F2 按第 5.10 节的 Schema/函数规格家族和类别分层规则单独分析，不套用仓库权重。

## 11. 依据与当前实现定位
