# 实验三独立方案：Orch 的交付成本、质量与时间

版本：E3-v1.0；编制与资料核查日期：2026-11-09。

状态：设计稿，尚未取数、未预注册、未执行。本次仅新增方案，不下载数据/镜像，不改引擎与实验代码，不发起模型调用。具体模型、数据 revision、任务 ID 和账单价格须在后续预实验及冻结时登记，本文不虚构已经取得的数据。

## 1. 推荐决定与研究目标

**首选 SWE-Bench Pro V2 的公开完整母集进行分层随机抽样，使用其原版隔离评测作为主质量标准；SWE-bench-Live 作为可选外部复验。** 不再沿用综合方案中“Verified 30+Live 30 混合作主集”的默认设计。综合方案保留历史，本独立方案是优先开展实验三时的最新设计。

研究问题：在相同任务、工具权限和资源上限下，强模型规划、确定式校验与编排、廉价模型执行，能否降低每成功交付成本，并将质量下降控制在预先认可的范围内？哪些任务具有时间收益，哪些任务仅节省费用？

质量主假设：Orch 混合模型方案相对强模型端到端的 resolved rate 差值不低于 −5 个百分点。成本主假设：满足质量非劣效后，每成功交付成本下降。不预先承诺四倍降本、绝对质量相等或全局最优。

## 2. 测评集的权威性、公信力及选择理由

### 2.1 主集：SWE-Bench Pro V2 Public

官方公开说明：V2 为 **642 个任务、11 个仓库**，提供需求、验证器、参考解、容器环境、文件校验摘要以及网络限制与干净环境复评工具。它是 2026 年 9 月发布的修订公开版本，不等同于原来 731 题的 v1，也不等同于早期论文的所有公开/私有任务总量。[官方 V2 说明](https://github.com/scaleapi/SWE-bench_Pro-os/blob/main/v2/README.md)

选择理由分为四项可核查证据：

| 依据 | 为什么符合本研究 | 证据与限制 |
|---|---|---|
| 有正式研究来源 | 基础 SWE-Bench Pro 工作发表在 ICML 2026/PMLR，具有可引用的方法与学术审查来源 | [论文出版页](https://proceedings.mlr.press/v306/deng26f.html)；同行评议针对基础工作，不能自动当成后来 V2 每个任务已被独立认证 |
| 是仓库级工程任务 | 与 Orch 规划、跨文件修改、执行、验收和整合的目标一致，比单函数算法题更适合测架构 | [原始论文](https://arxiv.org/abs/2509.16941)描述现实工程及长程任务；不保证所有题都适合并行 |
| 评测材料可公开复现 | 可保留原题及原验证器，第三方可以复核生成 patch 和最终成绩 | [官方仓库](https://github.com/scaleapi/SWE-bench_Pro-os)；本机可执行性、许可证和镜像仍须后续核验 |
| 修订版强调评测完整性 | 网络受限的 agent 阶段、全新环境重放 patch，可以降低运行时查答案和修改环境获得假通过的风险 | [V2 协议](https://github.com/scaleapi/SWE-bench_Pro-os/blob/main/v2/README.md)；这些机制不能消除训练期污染或证明测试覆盖所有需求 |

权威性在这里指有学术来源、明确维护方、公开材料、可复核标准以及对问题的审查机制，不是“某机构保证全部正确”。本实验不以 GitHub 星数或排行榜名次作为选集依据。

### 2.2 为什么不继续以 Verified 或旧 Pro 为主集

需要修正此前只强调 Verified 历史认可度的推荐。2026-02-23，OpenAI 发布分析，指出 Verified 的测试与训练污染问题并停止使用其衡量前沿能力；其“59.4%”指特定 138 题审计子集，不能写成整个 500 题的缺陷比例。[Verified 审计](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)

2026-07-08，OpenAI 又对旧版 SWE-Bench Pro 公开集报告较广泛的质量问题，并撤回先前推荐。该批评针对当时的 731 题公开版本；不能机械套用到后来的 V2，也不能因为 V2 发布就假定问题全部解决。[旧 Pro 审计](https://openai.com/index/separating-signal-from-noise-coding-evaluations/)

因此选择 V2 的理由是“公开、任务契合、具备较新的修订与复评机制”，不是“OpenAI 现在推荐它”，也不是“Pro 从未有争议”。启动前要复核所抽任务。不得将 GPL 等许可限制当成没有训练污染的证据。

### 2.3 补充集与排除选择

| 候选 | 本轮角色 | 理由 |
|---|---|---|
| SWE-bench-Live | 可选 40 题外部复验 | 官方项目提供滚动更新任务与可执行环境，并标明 NeurIPS 2025 Datasets & Benchmarks 研究来源；适合检查较新任务上的方向是否一致，但较新不等于未被训练 |
| SWE-bench Verified | 不进入默认主集 | 历史可比性仍有用，但不能忽略新的质量与污染争议；如将来做，只单列历史复现 |
| SWE-smith | 不进入默认主集 | 合成缺陷适合调试与错误机理分析，本轮要论证真实仓库任务上的经济收益 |
| HumanEval/MBPP | 不作为架构主集 | 单函数题不能充分承载依赖传递、独立整合和并行成本 |
| Pro V2 HARD-51 | 不单独作为默认主集 | 它按既有模型失败筛选，适合压力测试，但单独使用会改变任务分布；主母集中的 Hard 标签保留作描述，不据此选“对 Orch 有利”的题 |

Live 的来源、数据划分与环境以[官方项目](https://github.com/microsoft/SWE-bench-Live)为准；本方案不依赖私有测试访问，也不把公开论文等同于模型训练污染已经被排除。

## 3. 实验分组：四臂配对

H 为选定的强模型，L 为执行价格较低的模型。价格较低是按冻结 API 计费规则定义，不预设其能力一定更弱；“贵/便宜”不按订阅名称猜测。

| 臂 | 模型配置 | 架构 | 作用 |
|---|---|---|---|
| A：E-H | H 规划并执行 | 单 agent 端到端，可自测与自修复 | 主要质量/成本参照 |
| B：E-L | L 规划并执行 | 与 A 相同端到端外壳 | 最低价格模型参照 |
| C：O-H | H 规划、H 执行 | Orch 静态校验、确定式调度、任务验收与整合 | 与 A 比较编排的总效应 |
| D：O-L | H 规划、L 执行 | 与 C 相同 Orch | 与 C 比较替换执行模型，与 A 比较最终方案 |

主比较 D−A；机制比较 C−A、D−C；B 用来回答“直接换便宜模型是否已经足够”。四臂均完整计入规划、执行、自测和修复成本。

A/B 使用相同底层工具循环及基本权限；C/D 的 worker 尽量使用同一工具循环，只增加 Orch 分派提示和写集约束。若无法做到同外壳，则记录差异，解释为整个系统的比较，不声称只比较一个模型因素。

C/D 的规划和全部规划修补都用 H，最大规划尝试 3 次；任务级最多一次额外返工；不启用模型接替、人工澄清、失败后重规划或自动绕过契约。规划使用已有冻结版契约，**不等待实验二，也不在本轮临时引入新 DSL**。命令判据优先；无法避免模型 judge 时，C/D 用同一个冻结 judge 并计费，不能称整个验收零模型调用。

C/D 各自生成计划，不能免费借用另一臂的计划或成果。规划随机性属于被测系统，靠任务配对及预定重复评估；不能只重跑较差计划。端到端在相同总预算内可自行调用公开测试与修复，不能故意限制为一次代码生成。

## 4. 主集抽样与样本量

### 4.1 原则：代表性主样本，不预筛“适合并行”的题

在锁定的 V2 642 题母集中，先按重复来源家族去重、做环境与题目资格审查，再按仓库比例分层随机抽样。主样本保留单文件任务、共享文件导致串行的任务及不易拆分的任务；不因 Orch 不好拆就移除。三种依赖形状只用于事后按预定标签分层描述，不能反向决定主集配额。

默认种子 20261109，先按 instance_id 排序后随机排列。保存整套入选与备用顺序，所有臂使用同一题目。正式数初始目标 **120 个独立任务**；按各仓库合格题量比例以最大余数法分配，至少每个非空仓库 1 题，容量不足按预定规则回流其他仓库。保留每层母集量 N_h 和样本量 n_h，主估计使用权重 N_h/n_h；仓库等权宏平均另报，不能混为原母集总体成绩。

同一 issue/PR、同义需求、相同修复/故障家族不得跨预实验与正式集。若某仓库全数不具备可执行环境，公开说明该仓库缺失，研究总体缩为合格母集，不能继续声称覆盖完整 642 题。

### 4.2 资格审查不看模型成绩

资格条件：原需求及材料齐全；原验证器可重建；参考补丁在干净环境通过；空补丁未解决；相同结果连续复验两次；需求与强制测试无尚未解决的明显矛盾。审查由独立于被测模型的人员完成，保留排除理由。测试不通过不能靠删测试或改题变成“原版任务”。

官方发布的参考/空补丁门槛是来源证据，本地仍要对拟用题复验，不能把网页上的通过声明当成这里已经跑过。若后续审查发现两次结果不一致，进入不稳定清单，在 R0 前按同仓库备用次序替换；正式期发现的新问题保留原运行，按第 11 节处理。

### 4.3 分阶段规模

| 阶段 | 任务 | 臂/重复 | 运行量与结论用途 |
|---|---:|---|---|
| 预实验 P3 | 12 个，不进入正式集 | 四臂，各 1 次 | 48 次；验证环境、账单和预算，估计配对不一致率 |
| 正式主试验 M3 | 默认 120 个 | 四臂，各 1 次 | 480 次；主要质量、成本和时长结果 |
| 稳定性重复（可选） | 同一正式全样本 | 每臂追加 2 次 | 120 题时再加 960 次；必须在正式运行前决定启用，不能挑失败任务追加 |
| 并行副实验（可选） | 12 个有真实并行机会的正式题 | 并发 1/3，各 3 次 | 72 次新运行；固定计划，隔离并发度影响 |
| Live 外部复验（可选） | 40 个 | 四臂，各 1 次 | 160 次；独立报告，不混入主集成功率 |

正式规模在预实验后、正式模型结果产生前一次性确定。候选 N＝120/240/360，以主比较的 −5 个百分点非劣效界、单侧 α＝0.025、目标功效 80% 做配对二元模拟，计入分层抽样与预计不一致率。预实验小，须同时模拟较高不一致率情形；不能只用过于乐观的点估计。若预算或母集不足以达到目标，则固定可承担规模做区间估计，明确不保证确认非劣效，不放宽界值凑结论。

默认第一遍正式运行预先标为 primary；如果启用另外两次重复，全部结果都发布，平均通过率、方差和“三次都成功”作为稳定性指标。不能用三次中最好一次当 pass@1，也不能把三次重复算作三个独立任务。主终点仍按预先指定 primary 一次，避免根据重复结果挑种子和退化的聚类区间。

### 4.4 Live 外部集如何取

只在主试验配置冻结时登记启用。固定官方 Python 数据快照，按 issue 日期优先使用已核实存在、且晚于主集问题时间分布的任务；预选 4 个可重建仓库各随机抽 10 个、主集不重合。若没有满足日期/容量要求的快照，记录失败，不把“最新”当作已查证事实。其原始题目、验证器与干净环境评价保持原样。40 题用于效应方向和区间估计，不单独承诺 −5 个百分点非劣效的功效。

## 5. 任务材料与新增标注

不改写主任务需求，不把原题翻译成更清晰的题面。各臂拿到相同公开 instruction、起点仓库、基本规则及任务允许的工具；参考补丁、测试补丁、隐藏答案不进入 agent 可见目录。

每题补充以下研究标签，双人独立判定后裁决：

| 标签 | 依据 | 用途 |
|---|---|---|
| 原子需求及证据 | 只根据可见需求和合法仓库约定抽取，再独立核对隐藏测试 | 说明任务含义与覆盖缺口，不给某一臂额外提示 |
| 工作形状 | 独立单元/可并行/依赖链或扇入/共享文件约束，允许多标签 | 分层解释 Orch 的收益边界 |
| 可并行机会 | 至少两个可独立开展、写集分离且有真实汇合目标的单元 | 不能把“多文件”直接标成可并行 |
| 任务类型和规模 | 缺陷/功能/维护；公开元数据及参考改动规模（评测人员可见） | 描述难度分布，不把 gold 实现细节提示给模型 |
| 测试与环境 | 官方检查、保护路径、依赖、参考/空补丁结果、波动 | 区分题目问题、环境问题和模型错误 |
| 数据来源 | revision、原 ID、family、仓库起点、问题日期、许可 | 可复现和污染局限说明 |

不为主试验人工指定计划、分派或模型路由。若人工发现官方测试有遗漏，只记覆盖问题；可建立额外研究检查，但必须在 R0 前锁定、四臂一致、另列指标，不能悄悄改原版主分数。

## 6. 公平运行与外部评分

### 6.1 两层验收，防止 Orch 自己给自己打分

Orch 内部可以使用既有公开检查和其契约判据决定返工/整合。最终主评分来自 agent 不可见的官方 verifier，四臂相同。外部官方结果在运行结束后只评分，不反馈给任何一臂继续修代码。维护者提供的 Orch 固定整体验收配置不得偷含官方隐藏测试，它只引用四臂均可访问的公开检查。

每臂完成或截止时导出原仓库基线上的 patch；即使未自称完成或内部报失败，有可重放 patch 也交外部评分。内部失败与外部 resolved 分别记录。主要质量是外部 resolved，不能只给 Orch 额外附加内部成功门槛，也不能用内部通过替代外部通过。另报“系统声称成功且外部通过”的交付成功和错误报喜率。

### 6.2 遵守 V2 的锁定评测原则

- agent 阶段只允许模型 API 端点，禁用联网检索与访问代码托管/答案站；依赖与镜像在计时前准备。
- 记录实际网络策略和探针结果；只在提示词写“不要上网”不算技术隔离。
- 禁止 agent 读参考解、隐藏验证文件或修复提交历史。原 Git 起点用官方清理后的状态；不能把整个 benchmark 目录挂进工作区。
- 每份 patch 在全新环境复评，运行原版 verifier，不复用 worker 修改过的缓存/依赖/测试环境。发布 agent 环境自测成绩与干净环境成绩，主分数采用后者。
- 若存在越权改验证器/外部资源，记完整性失败并保留证据，不能因碰巧通过而判成功。

这些原则依据官方 V2 协议；本方案的自定义 agent/费用上限属于研究设置，因此结果名称是“V2 研究子集上的四臂对照”，不是直接申报官方榜单可比成绩。

### 6.3 相同资源上限

默认每 trial **50 分钟 agent 阶段、120 次实际模型 API 请求、10 美元实际 API 费用**，任何一项达到即停止发新请求。50 分钟与官方 V2 文档的任务时间预算一致；费用和请求限制是本研究额外设置。提前准备依赖、外部调度排队和最终隐藏评分单独计时，不算 agent 延迟；Orch 自己的建工作树、规划、调度、公开验收和整合必须计时。

Orch 并发上限 3；同一 task 最多一次额外修复。端到端可在共同总预算内继续工具循环、自测及修复，不人为匹配一个不同语义的“重试次数”。H/L 配置相同上下文可见范围和工具权限，各模型内部推理设置固定并记录。C/D 初稿和修补用相同 H 设置，judge 设置固定。

预算值可在预实验后统一改一次并预注册；不得为了某一臂调高。价格上限按可核对账单/代理计数执行，在途请求可能溢出，真实超额照记。若只能拿到顶层 CLI 调用数，不能声称控制了 120 次实际 API 请求；必须先补采集或把此限制明确改为可执行口径。

同一时间只运行一个被测 trial，trial 内 Orch 可并行，避免四臂抢同机资源。四臂相同 CPU/内存与容器配额，总资源对多个 worktree 共享；后端限流等外部情况记入日志。题目按仓库分块、块内平衡四臂先后位置随机运行，不能先跑完便宜臂再跑贵臂。

## 7. 指标定义

### 7.1 质量（主终点）

**Resolved rate**＝干净环境下原版 verifier 通过的任务比例，使用 primary 运行，按第 4 节抽样权重估计。只有问题修复/功能检查及回归检查均满足才通过；以冻结版本 verifier 的实际判定为准，不自行降低条件。没有 patch、无法应用、超时无有效交付、预算耗尽后仍未解决均记未解决。

外部质量、系统报告的成功率和其一致性分别报告。规划拒绝但已有 patch 恰好通过官方检查时，应如实记外部 resolved 及内部状态，而非改写证据。任何外部完整性违规按预定规则判失败。

### 7.2 成本（主经济终点）

全部模型费用包含规划、修补、worker 工具循环、judge、失败与传输重试。每任务费用 C_i 先按 request_id 账单归属；缺实际金额时使用冻结分项单价×用量并标“估算”，按缓存/输入/输出/推理字段定义避免重复计费。

主经济指标 **CPS＝加权平均单任务 API 费用/加权 resolved rate**，等价于该研究总体的每成功解决任务成本。不是只对成功任务求费用均值。零成功时 CPS 不可定义/趋于无穷，不记零。D/A 的 CPS 比小于 1 表示成本更低。另报告平均每任务费用比，避免 CPS 只因质量差异变化而难解释。

如果只可取得批次余额差，报告批次平均费用，不能虚构逐任务账单或逐题成本区间。订阅额度不等于零 API 成本：H/L 必须使用可比 API 计费口径，或明确只能做 token/额度研究，不能得出真实金额“四倍降本”。本机算力、外部容器/云主机和人工配置费用单列；API 降本不自动代表总拥有成本下降。

### 7.3 时间与工程次指标

- 端到端 agent 延迟：从 trial 启动到终态/截止，含所有架构自身开销；报告中位数、P90、截止未解决比例。
- 首次交付时间和最终交付时间分开；限定时间内成功曲线与限制平均成功等待时间一并报告。未成功 trial 的成功等待时间取上限，避免只统计成功者。
- CPU/内存峰值、模型总请求与 token、任务数/层数/实际并发、重写及返工、越界、合并冲突、固定写集导致的串行化。
- 可选静态质量：冻结规则下新增 lint 问题、修改规模/复杂度。它们不替代功能正确，也不合成不透明“综合质量分”。

## 8. 统计与结论规则

### 8.1 主要质量比较

Δq＝p_D−p_A；非劣效界 −0.05，单侧 α＝0.025。primary 每题只有一次预指定观测，保留 A/D 成败的配对表，不按独立两组比例检验。

采用匹配二元风险差的 score/精确区间方法，分层抽样使用预定权重及对应分层合并。若所选实现不能处理权重，正式抽样前改用登记的自加权设计或有验证依据的保守分层区间，不把非加权公式直接套入权重数据。统计实现和小样本/全通过例子的区间须在 R0 前验证；零不一致对不意味着不确定性为零，不能靠退化 bootstrap 得到 [0,0] 并宣布非劣。

只有双侧 95% 区间下界严格高于 −0.05 才认定质量非劣。差异不显著不等于持平；下界未过门槛时报告“尚不能确认非劣效”。−5 个百分点必须作为研究者可接受损失事前写明，不能根据观测结果修改。

### 8.2 成本检验与经济解释

先通过质量门槛，再检验 D/A 的 CPS 比。按仓库分层、任务家族配对 bootstrap 10,000 次（种子 20261109），每次重新计算成本均值、成功率和比值，保留分母为零导致的不可定义比例；不能丢弃这些重采样获得漂亮区间。

比值 95% 区间上界<1 才支持降本；上界<0.25 才支持“至少四倍降本”。若质量非劣未证实，仍展示成本效应，但结论只能是成本与质量的权衡。严格的 Pareto 改进还要求质量和时间等目标均无劣化，本研究“允许 5 个百分点损失的质量非劣+费用下降”不能称为严格 Pareto 最优。

机制对比 C−A、D−C、D−B 为次要检验家族，若给显著性结论用 Holm 校正。按仓库、语言、人工任务形状的分层效果给区间与样本量，探索交互不外推成普遍规律。只有 11 个来源仓库，主区间主要描述这些任务与仓库内的不确定性；不能把它解释为任意软件项目的保证。

### 8.3 重复与官方分数边界

可选重复每题先平均后以任务聚类，所有重复的配对 ID 保持；质量平均和 CPS 稳定性不改变 primary 假设结论。不得从三次取最好 patch，也不得把研究预算下的子集分数直接与不同 agent、不同预算的榜单数值比较。

## 9. 并行副实验：可选，主试验不依赖它

从主集人工预标注“有并行机会”的题中，按仓库分散随机抽 12 个；不足则按实际数量报告，不拼接无关 issue。为每题事前构造一份合法固定计划，验证其未使用隐藏答案。这份计划不进入四臂主试验。

在 D 配置下比较并发度 1 与 3，各 3 次，其他模型、计划、反馈预算和总 CPU/内存相同，随机平衡顺序。计划生成费用按相同数额计入两种配置的端到端比较，实际只生成一次的账单与反事实单任务成本分开登记，不能假装真实支付两次。

主报执行阶段 T_concurrency1/T_concurrency3、含固定规划开销的总时长比、质量差、API 成本与资源利用率。不用 A/D 的时间比充当并行收益；两者既换架构又换模型。

### 10.2 可以开始预实验的条件

- 能在隔离环境重现参考/空补丁结果，能独立导出 patch 并干净重评；参考解、隐藏测试和修复历史不泄露。

## 11. 异常、排除和停止

所有正式分配运行均入总表。模型格式失败、计划被拒、写集阻断、工具误用、超时、预算耗尽属于结果，不删。全机断电、已证实平台整体中断等外生事故有独立标记，主表保留；预注册敏感性分析中可按完整四臂任务块补跑一次，旧记录不覆盖，不从两次中选好结果。

正式期新发现 benchmark 本身有问题，由不知道臂成绩的审查者给证据。原 verifier 成绩保持；争议任务剔除后的敏感性分析四臂一起执行并公开影响，不能看哪臂受损再决定。若必须修改题目/验证器，则另立研究版本，不混进原版主分数。

模型身份、数据摘要、核心提示词或验证器变化时停止受影响块。正式样本量按第 4 节一次冻结，达到即停止；不得 p 值接近显著时追加。预算不足提前终止则明确标记不完整研究，不把停止解释为达成假设。

## 12. 工作量与预算边界

费用上限是设计值，不是支出预测或授权。以 10 美元/trial 名义上限计：

|---|---:|---:|

| 正式 120 题，单次 primary | 480 | 4,800 美元 |
| 预实验+120 题主试验 | 528 | 5,280 美元 |
| 正式 120 题，启用全部 3 次重复 | 1,440 | 14,400 美元，另加预实验 |

单次任务实际可能远低于上限，但旧 demo 的几分钱成本不能外推到 Pro 仓库任务。预实验后用完整失败/成功分布估计均值与 P90 费用、模型调用和耗时，统一调整上限并冻结。N=240/360 时 primary 正式运行量分别为 960/1,440，上限分别 9,600/14,400 美元；不得未经预算决定自动扩样。

若希望低投入起步，先完成 12 题×四臂预实验，再据实决定正式规模；单做预实验只能得到可行性与粗效应，不能证明质量不降。当前不会执行任何预算消耗。

## 13. 操作顺序与最终结果包

1. 只读核实 B0 和环境适配缺口，登记 H/L/计费方案；后续另行获得取数与实施安排后才下载固定版本。
2. 构建来源与资格流转表，预实验/正式/备用按家族隔离；验证参考解、空补丁、网络和隐藏材料隔离。
3. 完成必要适配与日志，跑 12 题预实验，记录所有失败；只修实验装置，不用正式题调参。
4. 做样本功效与预算模拟，决定 N、是否重复/Live/并行，登记版本 R0、抽样权重、分析方法和停止规则。
5. 随机配对执行四臂，截止时导出 patch，统一干净环境评分；冻结原始轨迹与账单。
6. 先核对分配数/终态、费用守恒、patch—评分关联，再按预注册输出质量差、CPS 比及任务形状分层。

交付物：数据 revision 与来源许可、题目 ID/家族/抽样权重、资格排除证据、版本与提示词摘要、全量匿名轨迹/patch/评分/账单、失败分类、原始及敏感性结果、统计说明和结论边界。不能再分发的材料提供合法重建说明，不能发布参考解给后续被测模型读取。

最少四张结果表：四臂原版 resolved 与内部报告一致性；质量差及非劣效区间；平均 API 费用与 CPS 比；耗时及形状分层。结论按证据分别写“质量非劣且降本”“费用降低但质量有损失/尚不确定”“无降本证据”，不以一个综合分数掩盖权衡。
